# novel-to-screenplay v2.1 变更说明

本次更新保持 `SCREENPLAY-SCENE-v2` 的三部分正文接口不变：本章基础信息、人物与场景简表、分场剧本。三部分不是固定三场；SC 场数仍按完整戏剧任务决定。

## 有效表演

- 连续问答、举证、裁决或身份/权力变化不再只检查台词是否齐全；关键句后需按原文支持写出会改变下一拍理解、节奏或行动的必要现场反应。
- 证据被看见、权力转移、物件易主、认主和裁决落定时，直接相关人物要以可见行为接住结果，不新增悔悟、立场改变或结局。
- 认主、真相落定、关键拒绝和重大判词可使用现场声音收束/恢复及既有声音动机呼应；不强制每场抽声，不新增背景音乐或传音能力。
- 精简仍只针对重复开场、同义解释和检查措辞，不删除有效动作、反应、停顿及感官反馈。

## 下游可拆镜检查

- 对改变位置、持物、伤损、优势或场景状态的关键动作，内部检查起点、路径、接触/受阻、反馈和结束位置。
- 明确会影响后续的取出、收起、换手、转交、落脚和离场，避免下游自行补出瞬移、穿模或物件凭空出现。
- 持物、站位、伤损、场景破坏与信息状态必须被后续继承；五项检查不作为固定标签输出到剧本正文。

## 原文歧义门禁

- `screenplay_trigger_audit.json` 升级为 `screenplay-trigger-audit-v2`，增加 `downstream_gate`。
- `ready` 表示没有会影响资产、实体编号/状态、参考图映射、镜头衔接、对白归属或结果正确性的未决歧义。
- `needs-resolution` 必须列出原文证据、问题、下游影响和所需决策；禁止由剧本、资产或视频阶段自行脑补。
- 非阻断文字备注单独记录，不因小问题停止整个流水线。

## 总控联动

- `novel-video-orchestrator` 的 screenplay 阶段需同时登记基准剧本和 v2 审计。
- 总控脚本只允许 `downstream_gate.status=ready` 的新剧本阶段标记 completed；有阻断歧义时保持 blocked，先处理依赖问题。
- 已完成旧章节不自动迁移或重做；新门禁用于之后新生成、重验或明确升级的剧本产物。

## 项目角色声线

通用 Skill 不写死具体角色。本机项目配置已将《我的嫁妆，谁也别想拿去飞升》的咪咪语言声线锁定为“正太奶凶奶音·软糯少年感”；巨兽低吼只作为动作音效。该项目配置和章节素材不上传仓库。

## 验证

- novel-to-screenplay 结构校验器通过正常样例、缺声线、伪造证据、旧结构、场次不一致、缺正文触发语句和错误规则版本等原有反例。
- 新增通过：ready 含阻断项会失败、needs-resolution 含有效证据会被正确识别、伪造歧义证据会失败。
- 总控门禁烟测通过：ready 审计可完成 screenplay 阶段，needs-resolution 审计不能完成该阶段。
- 两个更新后的 Skill 均通过结构快速校验。
