# 图片制作工作流

## 1. 生产前检查

确认人物、场景、道具提示词文件来自已通过审核的基准剧本。生产阶段不得修改这些文件的内容。优先使用带“单画面版”的场景和道具文件；人物继续使用既定三视图格式。

运行 `extract_image_jobs.ps1`。脚本只提取以下明确块：

- `【角色NN｜...】` 下的 `【独立生图提示词｜...】`；
- `【场景NN｜...】` 下的 `【生图 Prompt｜...】`；
- `【道具NN｜...】` 下的 `【独立生图提示词｜...】`。

输出后检查资产编号、名称、类型、适用分镜、提示词哈希、目标文件和操作结论。已有审核资产必须显示为 `reuse`，新资产显示为 `generate`。

## 2. 授权模型

独立调用时，用户可以授权单个资产或明确命名的一批资产。由总控执行时，用户要求开始、继续或恢复一个明确章节，即构成该章的运行范围授权：覆盖计划内每个资产的首次生成和最多一次自动重试，不需要逐项重复确认。

仅解析文件、核对复用、上传参考图、填写提示词并停在提交前，属于无额度预检。点击会创建图片任务的发送、生成、重新生成或变体按钮前，必须已有独立授权或总控状态中有效的章节级运行授权。购买额度、切换未指定账号、替换已审核文件和扩大章节范围不在运行授权内。

## 3. 逐项网页生产

1. 为当前资产打开一个ChatGPT新对话，不在其他资产对话中继续。
   - 人物资产执行额外隔离：一名角色对应一个唯一对话地址；本章还有其他待生成角色时，也必须逐人重新进入空白图片创建页。不得在上一角色结果下方继续发送下一角色提示词。
   - 提交前检查当前空白页没有历史用户消息；提交后检查正式对话地址未被本批次其他资产使用。任一检查失败均不得提交或登记。
2. 若任务是基于既有母图的状态更新，先上传所有已验证参考图；图片用途只按提示词和资产记录解释，不读取或导出浏览器存储。
3. 把 `image_jobs.json` 中的 `prompt` 原样填入输入框。以UTF-8文本比较页面回读值与任务值；换行差异可以标准化为 `\n`，文字内容必须完全一致。ChatGPT当前的ProseMirror输入框会让 `innerText` 额外增加空行，不能直接用它验收；当输入框由多个段落子节点组成时，应按子节点顺序取 `textContent` 并用单个 `\n` 连接，再计算长度和SHA-256。若页面结构变化，重新从可见输入框验证，不沿用旧选择器猜测。
4. 核对当前账号、附件数量、目标资产和输入框内容后提交一次。
5. 等待页面明确显示完成或失败。超时表示未知，不等于失败；先回到原对话检查，禁止另开对话重提。
6. 若页面一次返回多张候选图，全部下载并按 `-候选01`、`-候选02` 编号保存，再选一张复制为正式资产并登记。候选原文件始终保留，不得删除。

## 4. 下载和命名

新建资产的默认正式文件名为 `<资产编号>-<资产名称>.png`，例如 `PROP-DOC-01-V02-梧桐城城契.png`。同一次生成返回的原始结果使用 `<资产编号>-<资产名称>-候选01.png`、`-候选02.png` 依次保存；通过质检的选中候选复制为不带候选后缀的正式文件，候选原件继续保留。

正式文件、候选文件和已有复用文件承担不同职责：

- `asset_manifest.json` 和生产进度只把不带候选后缀的文件作为稳定正式路径；
- 同一内容的候选图不得冒充新的资产版本；
- 重新设计、状态变化或需要替换已审核内容时，分配新的资产版本编号，如从 `V01` 升为 `V02`，不得覆盖旧版本；
- 项目中已经存在并已审核的历史复用资产保持其真实文件名，不为了套用新格式而批量改名；清单继续记录其实际路径和哈希。

复制选中候选到正式路径前，若正式路径已存在，必须先确认它与选中候选哈希完全相同。哈希不同则停止，保留两者并为新内容分配新的资产版本编号，禁止静默覆盖。

浏览器临时下载完成后立即复制到章节或全局图片资产目录。项目引用的图片不得只留在浏览器临时目录。

## 5. 视觉质检

先运行机械检查，再用浏览器截图或客户端的图片查看能力检查实际画面。

### 人物

- 画面结构严格符合提示词规定的面部特写和三视图布局；
- 所有视图必须是同一人物，脸、发型、服装、配色和配件一致；
- 无多余人物、严重肢体畸变、裁头、裁手、裁脚或关键配件缺失；
- 有母图时，身份和固定造型不得漂移。

### 场景

- 必须是一幅连续单一画面，不是多宫格、拼贴、俯视图或概念板；
- 绝对空景，无人物、动物、灵宠、手部、倒影或人形剪影；
- 固定空间锚点、方向、时间和光线状态符合提示词；
- 不把可移动剧情道具或后续特效烘焙进基础场景。

### 道具

- 只出现一个目标道具和一个稳定状态；
- 无人物、动物、手部、道具副本、多视图、局部拼版或说明标签；
- 轮廓、材质、尺寸锚点、纹样和状态符合提示词；
- 不提前生成后续剧情状态，不凭空增加徽记、文字或部件。

轻微纹理差异、非剧情性小瑕疵可记录后通过。身份错误、主体数量错误、场景含角色、多视图、严重畸变或关键结构错误必须判为不通过。

## 6. 失败和重试

页面拒绝提示词、生成失败、下载失败或视觉质检失败时，记录完整错误和当前文件，状态设为 `retryable` 或 `blocked`。章节级运行授权下，明确的随机生成失败或视觉硬伤可使用原始完整提示词自动重试一次；第二次仍失败则设为 `blocked`。网页结果未知不算失败，不增加尝试次数，也不得盲目重提。若需要追加修正语句或改变提示词，停止并说明原因，原始提示词文件保持不变。

登录、验证码、安全校验、付费、额度不足、网页结构无法确认或结果状态未知时停止外部操作，保存断点并交还用户处理。
