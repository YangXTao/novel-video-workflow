# ChatGPT图片制作

## 输入要求

开始生产前取得：

1. 人物、场景或道具图片提示词文件，至少一类；
2. 章节目录和全局图片资产目录；
3. 已有 `asset_manifest.json` 或章节 `image_asset_registry.json`（可以没有，首次登记时创建后者）；
4. 本次实际生图范围的明确授权。用户要求开始、继续或恢复一个明确章节时，可由总控记录为章节级运行授权，无需逐项重复确认。

先完整读取 [references/workflow.md](references/workflow.md) 和 [references/asset-contract.md](references/asset-contract.md)。需要连接或操作ChatGPT网页时，再完整读取 [references/browser-mcp.md](references/browser-mcp.md)。
发生网页断线、错图、串会话、提示词提取越界或下载异常时，完整读取并按 [references/troubleshooting.md](references/troubleshooting.md) 恢复。

## 硬性边界

- 只通过 `chatgpt_image_playwright` MCP操作ChatGPT网页生图；禁止调用Codex内置ImageGen，也不默认切换到OpenAI API。
- 图片提示词正文是不可改写的生产输入。禁止压缩、概括、润色、重排、补写、翻译或删除；页面提交前必须逐字回读核对。
- 每个资产使用一个独立新对话，避免不同角色、场景和道具相互污染。
- 同一章需要新建多个角色时，每个角色必须各自使用全新的独立对话；禁止在同一对话连续生成不同角色，也禁止上传其他角色的参考图。若两个角色任务记录到同一对话地址，全部停止登记并重新隔离核对，避免撞脸、服饰串染和身份融合。
- `approved`、`reuse_approved` 且文件和哈希匹配的资产直接复用；`no_build` 项不得生成；不得为纯对白提及或不存在的实体虚构图片。
- 有参考母图或状态更新基准时，必须先验证真实文件并上传；无参考图时不得虚构映射。
- 独立调用时按用户点名范围授权；由总控执行时，章节级运行授权覆盖计划内首次生成及每个资产最多一次自动重试。不得用该授权购买额度、切换未指定账号、替换已审核文件或扩大章节范围。
- 任务状态未知时先检查当前对话和下载记录，禁止盲目重复提交。

## 执行摘要

1. 运行 `scripts/extract_image_jobs.ps1`，从原始Markdown中原样提取独立生图提示词并生成 `image_jobs.json`。
2. 初始化或读取 `image_progress.json`，从最早未完成资产继续。
3. 核对复用、免建图、目标文件和参考图；确认独立授权或总控记录的章节级运行授权后进入网页。
4. 每项新建ChatGPT对话，必要时上传已验证参考图，然后原样提交该资产的完整提示词。
5. 等待生成结果并下载到章节图片资产目录；正式图使用 `<资产编号>-<资产名称>.png`，多张结果先按 `-候选NN` 全部保留，再把通过质检的选中图复制为正式文件。不得覆盖已审核资产；内容发生变化时分配新的资产版本编号。
   - 下载辅助程序只能断开自身控制连接，禁止关闭专用Chrome或原结果对话页；下载成功后的标签页清理不得作为下载步骤的一部分。
6. 运行 `scripts/inspect_image_file.ps1` 做文件、尺寸、方向和哈希检查，再按资产类型做视觉质检。
7. 通过后用 `scripts/register_image_asset.ps1` 登记为 `approved`；未通过则保留原图并记录。章节级运行授权下最多自动重试一次，第二次仍失败则设为 `blocked`。
8. 用 `scripts/image_progress.ps1` 记录提交、下载、质检和失败原因，保证中断后可恢复。

## 完成条件

一个资产只有在图片已下载到稳定路径、文件可读、视觉质检通过、哈希已登记且进度为 `qa_approved` 后才算完成。所有新建项完成、复用项核验通过、免建图项没有被误生成，当前批次才算完成。
