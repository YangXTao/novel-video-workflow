# 小说视频总控

## 总控职责

创作阶段按 [references/isolated-creative-tasks.md](references/isolated-creative-tasks.md) 使用独立上下文子任务执行现有创作Skill；总控只交接完整输入、等待产物和验证原样交付，不在自身上下文代写。此机制不改变子Skill的原始内容规则，也不使浏览器/桌面可被多个任务并发控制。正常生产不增加独立的逐镜复审任务或用户人工签字；创作Skill按原规则自检后，自动继续资产适配、逐镜绑定及提交检查（以用户授权范围为限）。专项测试不作为每章必经阶段。

按依赖顺序调用现有专用 Skill，不复制、不改写它们的原始规则：

1. `novel-to-screenplay`
2. `character-image-prompts`、`scene-image-prompts`、`prop-image-prompts`
3. `chatgpt-image-production`
4. `video-prompts-v13`（委派同一工作流包内的独立小家 v13.1.1 规则 Skill）
5. `doubao-video-production`
6. `jianying-editing`（视频与整章审核通过后，按章启用）

图片和豆包网页分别使用当前 Codex 已加载的 `chatgpt_image_playwright`、`doubao_playwright` MCP；剪映通过 `computer-use:computer-use` Skill 操作 Windows 桌面。执行工具和登录/窗口状态必须现场验证，不能以 Skill 文件存在代替运行成功。

**进入 `image_production` 阶段前必须先确认当前 Codex 会话已加载 `chatgpt_image_playwright` MCP 工具**；进入 `video_production` 前同样确认 `doubao_playwright`。工具存在时直接使用当前 Codex 连接及其持久化浏览器配置，不部署、不启动本仓库 `tools/` 中的旧服务，也不改写 Codex MCP 配置。工具缺失或连接关闭时按 Codex 当前插件/MCP恢复方式处理并保留断点；不得另外启动第二套控制器争用同一配置目录。浏览器页面实际未登录、出现验证码或安全校验时才交由用户处理。

开始任何整章任务前，完整读取 [references/workflow.md](references/workflow.md) 和 [references/state-contract.md](references/state-contract.md)。使用 `scripts/orchestrator_state.ps1` 初始化、更新、验证和汇总章节状态。

视频提示词阶段读取 [references/combat-style-presets.md](references/combat-style-presets.md)：新项目默认启用 `high-energy-combat-v1`，并把其“传入正文”逐字交给 `video-prompts-v13`；项目配置可用 `video_prompt_generation.combat_style_preset` 选择同名预设或写 `none` 关闭，未知值不得静默回落。如果项目根目录存在 `novel_video_production_config.json`，另读取其中的V10规则生效章节、账号顺序、项目特殊恢复方式，以及可选的 `video_prompt_generation.additional_directive`。该附加创作要求只作为项目级用户要求原样传递；优先级为当前任务用户明确要求＞项目附加要求＞通用预设。账号名称、生效章节和特殊操作不得写死在通用 Skill 中。

将完整剧本、上游已有资产清单、用户期望总时长、允许的单镜时长集合及数量限制、模型与画幅要求交给 `video-prompts-v13`，由它规划分镜与每镜秒数并生成唯一的完整章节提示词Markdown。总控不提前划分S镜头或锁定秒数，不要求逐镜计划；提示词完成后才由视频制作阶段匹配账号和入口。用户明确锁定的历史产物继续沿用。

Seedance参考图数量属于制作约束，不由总控代写镜头：总控在调用 `video-prompts-v13` 时完整传入“每镜优先2—4张、软上限5张、平台硬上限10张；需精确保持身份的具名角色优先2人、原则上不超过3人”的约束，由该Skill在剧情允许时自行拆镜或调整同镜承载。完整章节提示词完成后，总控只为视频制作登记相邻镜头的连续性类型（`hard_continuation`、`soft_continuity`、`no_continuity`）和可用尾帧事实，不改写正文或图号；具体上传图选择由 `doubao-video-production` 完成。正文既有绑定超过软上限时交回 `video-prompts-v13` 重规划，不由总控或制作层删图。

## 不可破坏的约束

人物、道具、场景提示词同样按workflow.md的“三类图片提示词：完整输入直交”执行。三者分别读取同一份完整正式剧本及本类已有设定、真实资产和用户要求，自行清点、判定复用并按各自模板创作。总控不以预筛资产摘要替代剧本，不代写或统一加工输出。

视频提示词阶段按 [references/workflow.md](references/workflow.md) 的“完整输入直交”固定调用模板执行：整章生成明确指定“完整正式剧本、生成、完整档、不因篇幅降档”，交付整章正式剧本、已有设定、上游真实资产清单及用户时长/模型要求；用户明确指定其他模式或档位时除外。总控不预写分镜、不扫描图片、不增加计划或审计任务；该Skill独立规划后只交付一个完整章节Markdown，总控原样接回，不要求用户每章重复这些交接指令。

工作流不是另一个精简生成器：执行者必须读取 video-prompts-v13 入口，并按 video-prompts-v13/references/installed-rule-source.md 定位本工作流包中的小家 v13.1.1 规则源和当前任务适用的原规则，完整剧本不得替换为总控摘要。批量任务按母版完成创作及自身质检后原样汇总，不能用机械拆旧稿、拉伸时间戳或通用passed=true代替实际工作。恢复任务时重新读取此入口及子Skill当前合同，不能仅照旧章节脚本运行。

外围仅做输入、输出、提交三处交接检查：输入完整；唯一完整章节Markdown存在且正文未被二次改写；提交版本、真实图片、模型、时长、比例正确。内容质检由所属Skill按自身规则完成，总控不重复逐拍审计。未变化的正式产物沿用，仅复查修改项及受影响衔接。视频提示词阶段的输出侧另设**配额自检门禁**：接回后由总控独立重跑该阶段自检脚本，硬项非空或与交付说明不一致即退回该阶段（见 `video-prompts-v13/references/quota-selfcheck.md`）。

- 小说原文、基准剧本、各类图片提示词和V10镜头正文均按所属 Skill 原样处理。总控不得压缩、概括、润色、补写、合并或删减子 Skill 的生产输入和输出。
- 每阶段只读取上游已经通过验收的正式产物；文件路径和SHA-256写入 `chapter_pipeline_state.json`。路径缺失或哈希变化时，先回退到对应阶段核对。新版剧本还必须登记 `screenplay_trigger_audit.json`；其 `downstream_gate.status` 不是 `ready` 时，不启动依赖该歧义的资产或逐镜阶段。
- `asset_manifest.json` 是图片可用状态、真实路径、适用镜头和尾帧依赖的唯一依据；未实际生成并审核通过的图片不得映射。
- 视频制作开始前，`asset_manifest.json` 必须已经存在当前全部S镜的shots记录；每镜须登记关键身份节点对应的 `required_identity_assets` 和原因，纯画外音、不可辨认远景或静止背景角色才可显式豁免，并通过豆包制作Skill的绑定解析脚本。shots为空、核心身份图缺失或脚本未通过时，总控不得允许直接人工挑图进入网页提交。关键节点严格一致，非关键且不影响辨认、剧情和衔接的小幅偏差按小瑕疵通过。
- 当前视频提示词按 video-prompts-v13 的接口执行：顺序未知时用语义资产需求，正式图号必须对应真实上传顺序，不编造编号。历史锁定稿不自动改写。
- 视频提示词阶段的唯一正式交付是本章完整视频提示词 `.md`，默认命名为 `<章节名>_完整视频提示词.md`；用户要求时间戳命名或版本对比时追加 `_<YYYYMMDD_HHMM>`。文件按S编号顺序收录全部镜头。总控只确认文件存在且用户给定的总时长、允许时长和数量限制成立，不生成或要求逐镜切片、计划、映射、验证报告、哈希或封存文件，也不二次改写正文。接回后总控独立重跑该阶段配额自检脚本作门禁：硬项非空，或与交付说明结果不一致，即退回本阶段修订。
- V10规则升级只影响项目配置指定的生效章节；已经完成并被章节覆盖项锁定的旧章节继续使用其现有V10产物，不得自动追溯重写。
- 已审核正式文件、候选文件和重制留档均不得删除或静默覆盖。
- 新初始化章节默认启用 `editing`，执行剪映排片、视频原声字幕与个人预设“字幕-居中”，保留可编辑草稿，不导出、不加背景音乐。项目配置 `editing.enabled=false` 时初始化传 `-DisableEditing`。已有章节状态不自动迁移；用户明确要求该旧章剪辑时用 `EnableEditing` 启用，用户新指令优先于旧配置。

## 运行授权

用户要求“开始、继续或恢复”一个明确章节的生产时，视为该章节本次运行的范围授权：允许在该章内完成计划中的ChatGPT图片生成、豆包视频提交，以及每个资产或镜头最多一次生成结果硬失败后的自动重做（未创建视频的文字恢复不计实际视频候选，按视频制作Skill处理），无需逐项再次询问。该授权不扩展到其他章节、购买额度、付费操作、创建账号、读取浏览器敏感存储或擅自切换账号。

启用剪辑的章节还包括正常素材导入、排列时间轴、识别原声字幕、校对、应用个人预设和保存草稿。独立音频不在当前默认流程内。剪映登录/付费或桌面工具不可用时保留剪辑断点，已通过的上游产物保持可用。

登录、验证码、安全校验、付费购买、没有满足本镜参数的已授权可用额度路线、模型不可用、网页规则变化、任务结果无法判定，或同一资产/镜头连续两次硬失败时，停止受影响的依赖链并保存断点。可以继续与其没有依赖关系的阶段或镜头段。

豆包视频额度按账号、套餐、入口、模型/时长及页面确认的额度池/重置窗口记录；不再统一按每账号每日3次。只有明确创建的视频任务计视频次数，工作额度独立记录可见提示，池之间是否共享未知时不能叠加估算。可用的已授权账号/同参数路线耗尽后保存断点，不自动降低锁定模型或缩短时长。特殊账号的延后顺序和异常恢复只按项目配置执行。

## 视频质检策略

采用依赖感知的分段审核，不逐镜无限重做，也不等整章完成后才首次检查：

- 每个镜头下载后立即做技术检查和硬伤快检。
- 下一镜需要当前镜尾帧时，当前镜必须先通过结尾状态与尾帧门禁。
- 默认每完成3镜，或到达章节开头、匹配切、时空硬切等依赖边界时，执行一次完整内容审核。
- 小瑕疵记录后通过；具体范围以 `doubao-video-production` 的“分层质检与重做”为唯一执行口径，其中字幕属于允许的小瑕疵，不单独触发重做，水印仍按无水印交付规则处理。硬失败自动重做一次，第二次仍失败则阻断该连续性链；不得在新会话自行扩大硬失败范围。
- 上游重做后，只有人物身份、剧情状态、站位、机位构图或结尾状态发生实质变化时才复核下游；文件哈希变化本身不自动判定所有下游作废。

## 断点续做

每次恢复先验证磁盘正式产物、子流程进度文件和总控状态，再从最早的真实未完成依赖继续。不得仅根据网页是否打开、旧对话是否存在或状态表文字判断已经完成。

完成整章制作的条件是：剧本、三类资产提示词、图片资产清单和V10均已通过；所有镜头正式视频可读；所需尾帧已登记；每个质检批次通过；没有未解决的依赖阻断。启用 editing 的章节还必须有已验收、重开确认的可编辑剪映草稿及已登记的 editing_review.json。历史 not_enabled 章节沿用原完成条件；剪辑未完成时可以报告“视频制作完成”，不能报告“整章含剪辑完成”。
