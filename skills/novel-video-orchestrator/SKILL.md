# 小说视频总控

## 总控职责

按依赖顺序调用现有专用 Skill，不复制、不改写它们的原始规则：

1. `novel-to-screenplay`
2. `character-image-prompts`、`scene-image-prompts`、`prop-image-prompts`
3. `chatgpt-image-production`
4. `video-prompts-v10`
5. `doubao-video-production`

开始任何整章任务前，完整读取 [references/workflow.md](references/workflow.md) 和 [references/state-contract.md](references/state-contract.md)。使用 `scripts/orchestrator_state.ps1` 初始化、更新、验证和汇总章节状态。

如果项目根目录存在 `novel_video_production_config.json`，读取其中的V10规则生效章节、账号顺序和项目特殊恢复方式。账号名称、生效章节和特殊操作不得写死在通用 Skill 中。

## 不可破坏的约束

- 小说原文、基准剧本、各类图片提示词和V10镜头正文均按所属 Skill 原样处理。总控不得压缩、概括、润色、补写、合并或删减子 Skill 的生产输入和输出。
- 每阶段只读取上游已经通过验收的正式产物；文件路径和SHA-256写入 `chapter_pipeline_state.json`。路径缺失或哈希变化时，先回退到对应阶段核对。
- `asset_manifest.json` 是图片可用状态、真实路径、适用镜头和尾帧依赖的唯一依据；未实际生成并审核通过的图片不得映射。
- V10只写语义化“参考资产需求”；`@imageN` 只能由视频制作 Skill 在提交前根据真实上传顺序生成。
- V10规则升级只影响项目配置指定的生效章节；已经完成并被章节覆盖项锁定的旧章节继续使用其现有V10产物，不得自动追溯重写。
- 已审核正式文件、候选文件和重制留档均不得删除或静默覆盖。
- 剪辑阶段固定为 `not_enabled`，直到用户以后明确启用剪辑能力。

## 运行授权

用户要求“开始、继续或恢复”一个明确章节的生产时，视为该章节本次运行的范围授权：允许在该章内完成计划中的ChatGPT图片生成、豆包视频提交，以及每个资产或镜头最多一次自动重试，无需逐项再次询问。该授权不扩展到其他章节、购买额度、付费操作、创建账号、读取浏览器敏感存储或擅自切换账号。

登录、验证码、安全校验、付费购买、账号额度耗尽、模型不可用、网页规则变化、任务结果无法判定，或同一资产/镜头连续两次硬失败时，停止受影响的依赖链并保存断点。可以继续与其没有依赖关系的阶段或镜头段。

豆包视频额度按账号、按天记录；默认每个账号每天最多3次正式创建的视频任务。只有页面明确确认视频任务已创建才计数，达到3次后在下一镜提交前自动切换到下一个可用账号。特殊账号的延后顺序和异常恢复只按项目配置执行。

## 视频质检策略

采用依赖感知的分段审核，不逐镜无限重做，也不等整章完成后才首次检查：

- 每个镜头下载后立即做技术检查和硬伤快检。
- 下一镜需要当前镜尾帧时，当前镜必须先通过结尾状态与尾帧门禁。
- 默认每完成3镜，或到达章节开头、匹配切、时空硬切等依赖边界时，执行一次完整内容审核。
- 小瑕疵记录后通过；硬失败自动重做一次，第二次仍失败则阻断该连续性链。
- 上游重做后，只有人物身份、剧情状态、站位、机位构图或结尾状态发生实质变化时才复核下游；文件哈希变化本身不自动判定所有下游作废。

## 断点续做

每次恢复先验证磁盘正式产物、子流程进度文件和总控状态，再从最早的真实未完成依赖继续。不得仅根据网页是否打开、旧对话是否存在或状态表文字判断已经完成。

完成整章制作的条件是：剧本、三类资产提示词、图片资产清单和V10均已通过；所有镜头正式视频可读；所需尾帧已登记；每个质检批次通过；没有未解决的依赖阻断。剪辑不计入当前完成条件。
