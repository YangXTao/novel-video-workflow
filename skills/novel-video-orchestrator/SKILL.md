# 小说视频总控

## 总控职责

按依赖顺序调用现有专用 Skill，不复制、不改写它们的原始规则：

1. `novel-to-screenplay`
2. `character-image-prompts`、`scene-image-prompts`、`prop-image-prompts`
3. `chatgpt-image-production`
4. `video-prompts-v12`
5. `doubao-video-production`
6. `jianying-editing`（视频与整章审核通过后，按章启用）

图片和豆包网页分别使用 `chatgpt_image_playwright`、`doubao_playwright` MCP；剪映通过 `computer-use:computer-use` Skill 使用 `node_repl` 与 `@oai/sky` 操作 Windows 桌面。执行工具和登录/窗口状态必须现场验证，不能以 Skill 文件存在代替运行成功。

开始任何整章任务前，完整读取 [references/workflow.md](references/workflow.md) 和 [references/state-contract.md](references/state-contract.md)。使用 `scripts/orchestrator_state.ps1` 初始化、更新、验证和汇总章节状态。

如果项目根目录存在 `novel_video_production_config.json`，读取其中的V10规则生效章节、账号顺序和项目特殊恢复方式。账号名称、生效章节和特殊操作不得写死在通用 Skill 中。

用户需要分配10/15/30秒、选择模型或按套餐安排产能时，读取 [references/duration-and-model-planning.md](references/duration-and-model-planning.md)，并读取视频制作Skill的 `references/generation-routes-and-quota.md`。先按剧情与一致性目标形成制作计划，再生成完整提示词；建议不自动成为已批准默认，旧章不追溯改写。

## 不可破坏的约束

- 小说原文、基准剧本、各类图片提示词和V10镜头正文均按所属 Skill 原样处理。总控不得压缩、概括、润色、补写、合并或删减子 Skill 的生产输入和输出。
- 每阶段只读取上游已经通过验收的正式产物；文件路径和SHA-256写入 `chapter_pipeline_state.json`。路径缺失或哈希变化时，先回退到对应阶段核对。新版剧本还必须登记 `screenplay_trigger_audit.json`；其 `downstream_gate.status` 不是 `ready` 时，不启动依赖该歧义的资产或逐镜阶段。
- `asset_manifest.json` 是图片可用状态、真实路径、适用镜头和尾帧依赖的唯一依据；未实际生成并审核通过的图片不得映射。
- 当前视频提示词按 video-prompts-v12 的接口执行：顺序未知时用语义资产需求，正式图号必须对应真实上传顺序，不编造编号。历史锁定稿不自动改写。
- 视频提示词阶段必须登记一个本章完整视频提示词 `.md` 正式文件、全部逐镜工作切片、`video_prompt_compliance_audit.json` 和 `video_prompt_validation.json`。完整Markdown必须按S编号顺序覆盖本章计划内全部镜头，单个S文件或若干散片不能代替整章交付。总控必须读取验证报告并确认 `status=passed`，同时核对报告中的整章文件路径与哈希；否则保持该阶段未完成并退回video-prompts-v12修订。不得因单镜文件已存在、用户未提醒或模型声称“严格执行”而放行豆包生产。门禁无权另设母版之外的拍数、内容或格式规则。
- V10规则升级只影响项目配置指定的生效章节；已经完成并被章节覆盖项锁定的旧章节继续使用其现有V10产物，不得自动追溯重写。
- 已审核正式文件、候选文件和重制留档均不得删除或静默覆盖。
- 新初始化章节默认启用 `editing`，执行剪映排片、视频原声字幕与个人预设“字幕-居中”，保留可编辑草稿，不导出、不加背景音乐。项目配置 `editing.enabled=false` 时初始化传 `-DisableEditing`。已有章节状态不自动迁移；用户明确要求该旧章剪辑时用 `EnableEditing` 启用，用户新指令优先于旧配置。

## 运行授权

用户要求“开始、继续或恢复”一个明确章节的生产时，视为该章节本次运行的范围授权：允许在该章内完成计划中的ChatGPT图片生成、豆包视频提交，以及每个资产或镜头最多一次自动重试，无需逐项再次询问。该授权不扩展到其他章节、购买额度、付费操作、创建账号、读取浏览器敏感存储或擅自切换账号。

启用剪辑的章节还包括正常素材导入、排列时间轴、识别原声字幕、校对、应用个人预设和保存草稿。独立音频不在当前默认流程内。剪映登录/付费或桌面工具不可用时保留剪辑断点，已通过的上游产物保持可用。

登录、验证码、安全校验、付费购买、没有满足本镜参数的已授权可用额度路线、模型不可用、网页规则变化、任务结果无法判定，或同一资产/镜头连续两次硬失败时，停止受影响的依赖链并保存断点。可以继续与其没有依赖关系的阶段或镜头段。

豆包视频额度按账号、套餐、入口、模型/时长及页面确认的额度池/重置窗口记录；不再统一按每账号每日3次。只有明确创建的视频任务计视频次数，工作额度独立记录可见提示，池之间是否共享未知时不能叠加估算。可用的已授权账号/同参数路线耗尽后保存断点，不自动降低锁定模型或缩短时长。特殊账号的延后顺序和异常恢复只按项目配置执行。

## 视频质检策略

采用依赖感知的分段审核，不逐镜无限重做，也不等整章完成后才首次检查：

- 每个镜头下载后立即做技术检查和硬伤快检。
- 下一镜需要当前镜尾帧时，当前镜必须先通过结尾状态与尾帧门禁。
- 默认每完成3镜，或到达章节开头、匹配切、时空硬切等依赖边界时，执行一次完整内容审核。
- 小瑕疵记录后通过；具体范围以 `doubao-video-production` 的“分层质检与重做”为唯一执行口径，其中字幕属于允许的小瑕疵，不单独触发重做，水印仍按无水印交付规则处理。硬失败自动重做一次，第二次仍失败则阻断该连续性链；不得在新会话自行扩大硬失败范围。
- 上游重做后，只有人物身份、剧情状态、站位、机位构图或结尾状态发生实质变化时才复核下游；文件哈希变化本身不自动判定所有下游作废。

## 断点续做

每次恢复先验证磁盘正式产物、子流程进度文件和总控状态，再从最早的真实未完成依赖继续。不得仅根据网页是否打开、旧对话是否存在或状态表文字判断已经完成。

完成整章制作的条件是：剧本、三类资产提示词、图片资产清单和V10均已通过；所有镜头正式视频可读；所需尾帧已登记；每个质检批次通过；没有未解决的依赖阻断。启用 editing 的章节还必须有已验收、重开确认的可编辑剪映草稿及已登记的 editing_review.json。历史 not_enabled 章节沿用原完成条件；剪辑未完成时可以报告“视频制作完成”，不能报告“整章含剪辑完成”。
