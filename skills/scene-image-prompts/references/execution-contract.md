# 场景图片提示词当前执行合同

本文件不替代、不精简 `original-prompt.md`。成品必须同时满足原始规则和本合同；如旧规则仍出现六格、多宫格或多视图要求，以本合同的“单一画面锁”为准。

## 一、禁止自行精简

- 禁止以地点相似、避免重复、节省篇幅或提高可读性为理由，省略资产清单、复用说明、无需建图说明、适用分镜、环境解析、完整提示词或资产小结。
- 每个需要新建或更新的场景提示词必须完整自包含；不得写“同上”“参照前一场景”“其余一致”或用关键词提纲代替自然语言空间描述。
- 描述长度由空间结构、固定锚点、材质、光影和视频复用需求决定，不设人为字数上限。

## 二、筛选、映射与数量闭环

- 必须先扫描完整剧本，区分实际出现地点、纯对白提及地点、过渡背景、同地别名和稳定状态版本。
- 同一地点的全称、简称、别名，以及单纯更换机位、景别或人物站位，合并为同一场景；绝不重复生成。
- 清单中每一项都必须有明确处理结果：沿用、新建单一场景图、更新状态单一场景图或无需建图。
- 每个“新建”或“更新状态”条目必须且只能对应一个完整场景分块；沿用和无需建图条目不得重复生成。
- 场景名称前必须准确列出该场景实际使用的全部S编号。纯对白提及地点不得写入适用分镜。

## 三、单一画面锁

- 每个资产版本只能生成一幅连续、完整、统一透视的单一环境画面。
- 严禁多宫格、拼贴、概念设定板、故事板、三视图、多角度展示、正反面同图、俯视平面图、色板、分割线、边框、说明箭头、尺寸线、标题、文字标签和同图多状态。
- 只允许一个时间状态、一个主机位、一个统一光源逻辑和一个连续空间。不得在同一图中同时展示白天与夜晚、完整与坍塌、法阵关闭与开启等不同版本。
- 画面必须采用横向16:9的宏观广角大景别，呈现宏大、完整、具有空间纵深和影视可用性的环境。使用GPT Image 2 API时采用3840×2160、quality: high；界面无法指定像素时选择可用的最高质量横向输出。
- 画面四周保留安全边距，核心建筑、出入口、地面和固定锚点不得被裁切。不要把场景画成白底模型、建筑剖面、平面图或产品展示台。

## 四、绝对空景与内容边界

- 场景图绝对不能出现人物、角色、动物、灵宠、妖兽、手部、肢体、人形剪影、人物倒影或拥挤群众。
- 仅呈现环境、建筑、自然风光、固定家具、不可轻易移动的陈设、材质和光影氛围。
- 可被角色拿取、交接或移动的剧情核心道具不得固定烘焙进基础场景图；需要独立保持一致时交由道具Skill处理。
- 原文没有的建筑、房间、道路、固定陈设、空间连接、法阵、灾害或装饰不得为了“宏大”而新增。

## 五、中文提示词与画风

- 资产表、复用说明、环境解析、最终生图 Prompt 和资产小结全部使用中文；PBR、Unreal Engine 5、GPT Image 2等通用技术名称可以保留。
- 每份提示词自然融入：高精度3D半写实国漫、次世代游戏CG质感、Unreal Engine 5渲染、8K级细节、杰作级画面、电影级光影、超精细。
- 每份提示词必须明确包含：广角大景别、宏大尺度、空场景、无人物、无角色、无动物、单一画面，以及该场景真实的空间结构、材质、主色、默认光源和固定锚点。

## 六、复用与状态版本

- 只有当前实际提供或用户明确确认可沿用的场景资产，才能判为已有资产。
- 人物、动作、可移动道具或机位变化不建立新场景；稳定且明显的环境状态变化才建立版本。
- 状态版本必须继承基础场景的空间结构和固定锚点；只有剧本明确发生结构损毁时才能改变拓扑。

## 七、交付前核对

交付前逐项核对：清单闭环、分镜映射准确、同地去重、每个新建或更新项只有一个连续画面、绝对空无角色、中文提示词完整、空间锚点清晰、没有多宫格或文字标签、资产小结包含空间拓扑。发现缺项必须补齐，不能用“篇幅较长”解释省略。

如果聊天消息不足以承载完整成品，应优先把完整内容写入用户指定文件并交付文件，不能改为摘要版。
