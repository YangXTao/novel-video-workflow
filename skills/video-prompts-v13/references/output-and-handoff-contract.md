# 输出与下游交接合同（沿用原入口，替换版本标识）

本文件承接 v12.6 旧入口既有的下游合同，只把规则源与版本标识换成 v13.0。内容规则一律以安装版 skill 原文为准，本文件不新增任何创作要求。

## 1. 唯一交付物

- 每章**一个**完整视频提示词 Markdown：`<章节名>_完整视频提示词_v13.0.md`
  （仅当用户要求版本对比时追加时间戳；历史锁定稿的文件名与内容都不自动改写）。
- 文件按 S 编号顺序收录**全部**镜头，逐镜正文完整，不做逐镜切片、不发计划、映射、验证报告、哈希或封存文件。
- 中间产物（规则卡、依赖清单、证据回执、状态账本）只在创作子任务内部静默存在，不落盘为交付物。

## 2. 逐镜自包含（下游可直接提取）

制作层按 S 编号从该 Markdown 提取每镜正文，提取结果直接作为提交正文，因此每镜必须自身闭环：

- 打戏镜头按其规则源的固定四段式（画质基准 → 角色·场景·核心设定 → 时间轴 → 负面提示词）自包含，另附全局正向词；不得使用"同上/同前/画质同前"。
- 承接关系写在正文内（承接拍），不依赖上一镜文件。
- 内部编号、分支名、规则名、工程参数不得出现在正文；`Time Ramp` 等只在画质基准内保留。

## 3. 图号与参考图预算

- 逐镜本地图号：每镜自己引用的真实参考图从 `@image1` 连续编号，同镜同图不重复，不把全章资产序号当 `@imageN`。
- 只选本镜真实可用资产，不引用无关角色；资产 ID 跨章稳定。
- Seedance 参考图：每镜优先 2—4 张，软上限 5 张，平台硬上限 10 张；需精确保持身份的具名角色优先 2 人、原则上不超过 3 人。
- 硬直续镜头须为上一镜尾帧预留 `@image1` 并减少重复人物/场景参考；软衔接与无衔接不预留尾帧。
- 超过软上限时：先按规则源拆镜或降低同镜身份承载；确实不可拆且不超过平台上限时，在交付中写明哪些参考图不可替代，供制作层登记例外理由。制作层不得擅自删正文绑定或把关键实体改成纯文字。

## 4. 连续性三分类（总控登记，不创作镜头）

落盘后由总控按相邻镜头已写明的时空/人物/动作/物件状态登记，不改写正文与图号：

- `hard_continuation`：同一时空同一主体、下一镜从上一镜结束状态直接起步 → 需要上一镜已审核尾帧。
- `soft_continuity`：同场景或同事件但已换机位/景别/动作阶段 → 通常不上传尾帧。
- `no_continuity`：新场景、新时间、闪回、梦境、明确硬切 → 不得上传尾帧。

绑定由 `doubao-video-production` 按每镜正文与真实 `asset_manifest.json` 完成，并须通过其绑定解析脚本。

## 5. 交接检查（总控查外围三项 + 配额自检门禁）

1. **输入完整**：完整正式剧本、已有设定、真实资产清单、制作要求（总时长与口径、允许单镜时长、各档数量限制、模型与画幅）、项目级附加创作要求、锁定内容与衔接事实，逐项到位。
2. **产物唯一且未二次改写，并附配额自检结果**：完整章节 Markdown 存在、只此一份、正文哈希未被下游修改；总控只核对总时长、允许秒数、各档数量上限、模型/比例、对白原句与归属。交付必须附本章配额自检结果（A–E 五段），硬项为空；软项偏差已在交付说明中逐条披露。
3. **提交正确**：制作层的版本、真实图片、模型、时长、比例与正文一致。

有缺项时把**具体位置与问题**交回本层修订，不得由总控或制作层自行补写正文。

**配额自检门禁**：总控接回后按 `quota-selfcheck.md` 独立重跑自检脚本（机械校验，不是逐拍内容审计）。硬项非空，或重跑结果与交付说明不一致时，退回本层修订；总控不得改写正文、不得放宽判读口径。自检通过不等于内容合规——运镜动机闸、戏成立终审、剧本逐句映射与内部口径泄漏仍由本层按规则源完成。
