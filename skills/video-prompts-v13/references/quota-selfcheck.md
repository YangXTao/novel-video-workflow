# 配额自检（出稿后强制）

本文件规定 `video-prompts-v13` **交付前必须完成**的自动配额自检。

它是**工作流侧验收合同**，不是创作规则：不新增任何创作要求、不改变规则源任何内容、不替代规则源自身的 70 号质检与 96 号最终放行闸。规则源仍在安装目录只读存在。

## 1. 定位自检脚本（三步，先命中先用）

1. **项目配置**：项目根目录 `novel_video_production_config.json` 中的 `video_prompt_generation.quota_checker`（绝对路径或 `~` 开头）。
2. **环境变量**：`XIAOJIA_QUOTA_CHECK`。
3. **默认安装位置（WorkBuddy）**：`~/.workbuddy/skills/storyboard-quota-check/scripts/quota_check.py`
   （本工作流当前**只接 WorkBuddy**。）

Python 解释器解析顺序：项目配置 `video_prompt_generation.quota_checker_python` → 环境变量 `XIAOJIA_QUOTA_PYTHON` → 运行环境自带 python。

脚本缺失或不可运行时**不要新建、不要复制、不要临时改写**：按 §3 停机处理。

## 2. 运行

```text
<python> "<quota_checker>" "<本章完整视频提示词MD路径>" --max15 <N>
```

- `--max15 N` 取用户给定的「>10s 镜数量上限」。用户未给定时省略该参数（脚本默认 3），并在交付说明里注明使用了默认值。
- 镜标题缺 `（N秒）` 声明时追加 `--dur N`。
- 脚本只读稿子，不写任何文件；可一次传多份做对比。

## 3. 判读与处置（硬项与软项分开处理）

| 段 | 内容 | 处置 |
|---|---|---|
| A 章节级 | 镜数、总时长、时长分布、>10s 镜计数与上限、全稿总字数 | 与用户给定规格逐项比对，不符即返工 |
| B 逐镜 | ①②③④ 字数、拍数、拍相加、拍长序列 | 拍相加≠声明时长、④段>300、拍长出 220–280 → 返工 |
| C 证据项 | `@image` 锚定数、承接复述数、占画框数、隐形剪辑点数 | 非首镜 `recap=0`、`img` 显著为 0 → 返工 |
| D 硬项/软项 | 硬项＝必修；软项＝已知同级规则冲突 | **硬项为空才可放行**；软项保留时逐条披露 |
| E 运镜标签越界 | ③段方括号标签不在规则源清单内（附镜号） | 形如视觉目标（`跟*`/`展*`/`聚焦*`）的越界 → 按铁律52 改用规则源用词后**重跑自检** |
| F 锁死画质原文覆盖率 | ①段对「打戏 11 号 2.1 / 文戏 20 号 3.1」锁死原文的特征表述命中率 | **信息项，不做通过/否决**。覆盖率 <60% ＝疑似没读就编，交人工核；字面未命中不代表违规（规则要求压成散文），未命中清单用于**指出该人工核语义的位置** |
| G 尺度四件套代理 | 逐拍统计「画框分数占比」「参照物」覆盖率，列出疑似特效拍却无画框分数的疑点拍 | **信息项**。按「拍」统计而铁律19 判据是「句」，会低估；只用于定位该人工核的位置 |
| H ②段必备要件与图号一致性 | ①三混合配比%（三项合计 100）②场景五层 ③③段图号可追溯 ④图号-实体疑似错配 | ①②③ 为**硬项**（非空即返工）；④ 为**启发式信息项**，须人工确认后交回执行层改，脚本与总控都不改正文 |
| I 特效落实 | 铁律19 尺度四件套与九要素⑨、铁律33 巨物感三连、铁律5 爆点量级、12 号 2.9.1 并行特效类 | **信息项，不做通过/否决**（"什么算大特效镜/巨物镜"须人工判断）。某项全稿普遍未检出时，优先怀疑该镜没读到对应规则子节，连同镜号交回执行层核 |

- **硬项违规非空 → 不得交付**：回生成阶段修改，改完必须重跑自检，不得沿用修改前的结论。
- **软项偏差**属①/②段与铁律54 的已知同级冲突（画质基准锁死原文、法阵/法相/资产完整锁定）。保留时必须在交付说明中逐条列出镜号与实测字数，**不得静默放过**。
- **脚本不可用或缺失** → 停机，报出实际路径与失败原因；**不得伪造自检结论，也不得声称「已按规则自检」**。此时交付说明必须显式写明「未跑自动自检」。

## 4. 交付说明必带的三项（硬要求）

自检结果之外，交付说明还必须写明以下三项——目的是让"用的是哪一版规则""实际读了哪些子节"可被外部核对：

1. **规则源标识**：解析到的实际路径 + `metadata.version` + `SKILL.md` 的 SHA-256。证明用的是哪一版规则源，而非凭记忆或旧版。
2. **实际读取的文件与子节清单**：逐项列出读了哪些 `references/` 文件、各读了哪些子节编号（对应 96 号契约的依赖清单）。**这是自报证据，不能独立验证**，但强制枚举本身能压掉"只读标题就落稿"，并让你可以定点抽查某条子节。
3. **自检结果**：A–I 各段原样附上（不是结论摘要）。

三项都只出现在**交付说明**里：不进提示词正文、不落盘为交付物、不生成独立报告文件。

## 5. 证据边界

- 自检输出（A–I 各段）随交付说明返回给总控，**不写入提示词正文**、不落盘为交付物、不生成独立报告/哈希/封存文件。
- 总控接回后**独立重跑同一脚本**作为该阶段门禁；两次结果应一致，不一致即回退本阶段核对。重跑是机械校验，不是逐拍内容审计。
- 自检通过不等于内容合规：运镜动机闸、戏成立终审、剧本逐句映射、画质词是否真为 11 号 2.1 原文、正文是否泄漏内部口径、以及**特效是否真按铁律19/33/38/5 与 12 号 2.9.1 落实**，这几项脚本查不到或只能检出字面证据，仍由本层按规则源 70 号与 96 号完成。I 段专门用于把"该人工核的特效位置"标出来，不代替人工核。

## 6. 与规则源的关系

自检脚本是工作流侧工具，不被规则源引用、不修改规则源、不进 `~/.workbuddy/skills/xiaojia-prompt-generator`。规则源升级后本层无需改动；但若规则源改变成稿结构（四段式标记或拍的行首写法），需同步更新脚本的解析规则。
