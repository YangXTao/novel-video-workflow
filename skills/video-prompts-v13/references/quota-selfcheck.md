# 配额自检（出稿后强制）

本文件规定 `video-prompts-v13` **交付前必须完成**的自动配额自检。

它是**工作流侧验收合同**，不是创作规则：不新增任何创作要求、不改变规则源任何内容、不替代规则源自身的 70 号质检与 96 号最终放行闸。规则源仍在安装目录只读存在。

## 1. 定位自检脚本（三步，先命中先用）

1. **项目配置**：项目根目录 `novel_video_production_config.json` 中的 `video_prompt_generation.quota_checker`（绝对路径或 `~` 开头）。
2. **环境变量**：`XIAOJIA_QUOTA_CHECK`。
3. **默认安装位置（按运行环境依次尝试）**：
   - WorkBuddy：`~/.workbuddy/skills/storyboard-quota-check/scripts/quota_check.py`
   - Codex：`~/.codex/skills/storyboard-quota-check/scripts/quota_check.py`

Python 解释器解析顺序：项目配置 `video_prompt_generation.quota_checker_python` → 环境变量 `XIAOJIA_QUOTA_PYTHON` → 运行环境自带 python。

脚本缺失或不可运行时**不要新建、不要复制、不要临时改写**：按 §3 停机处理。

## 2. 运行

```text
<python> "<quota_checker>" "<本章完整视频提示词MD路径>" --max15 <N>
```

- `--max15 N` 取用户给定的「>10s 镜数量上限」。用户未给定时省略该参数（脚本默认 3），并在交付说明里注明使用了默认值。
- 镜标题缺 `（N秒）` 声明时追加 `--dur N`。
- 脚本只读稿子，不写任何文件；可一次传多份做对比。

## 3. 判读与处置（硬项与软项分开处理）

| 段 | 内容 | 处置 |
|---|---|---|
| A 章节级 | 镜数、总时长、时长分布、>10s 镜计数与上限、全稿总字数 | 与用户给定规格逐项比对，不符即返工 |
| B 逐镜 | ①②③④ 字数、拍数、拍相加、拍长序列 | 拍相加≠声明时长、④段>300、拍长出 220–280 → 返工 |
| C 证据项 | `@image` 锚定数、承接复述数、占画框数、隐形剪辑点数 | 非首镜 `recap=0`、`img` 显著为 0 → 返工 |
| D 硬项/软项 | 硬项＝必修；软项＝已知同级规则冲突 | **硬项为空才可放行**；软项保留时逐条披露 |
| E 运镜标签越界 | ③段方括号标签不在规则源清单内（附镜号） | 形如视觉目标（`跟*`/`展*`/`聚焦*`）的越界 → 按铁律52 改用规则源用词后**重跑自检** |

- **硬项违规非空 → 不得交付**：回生成阶段修改，改完必须重跑自检，不得沿用修改前的结论。
- **软项偏差**属①/②段与铁律54 的已知同级冲突（画质基准锁死原文、法阵/法相/资产完整锁定）。保留时必须在交付说明中逐条列出镜号与实测字数，**不得静默放过**。
- **脚本不可用或缺失** → 停机，报出实际路径与失败原因；**不得伪造自检结论，也不得声称「已按规则自检」**。此时交付说明必须显式写明「未跑自动自检」。

## 4. 证据边界

- 自检输出（A–E 五段）随交付说明返回给总控，**不写入提示词正文**、不落盘为交付物、不生成独立报告/哈希/封存文件。
- 总控接回后**独立重跑同一脚本**作为该阶段门禁；两次结果应一致，不一致即回退本阶段核对。重跑是机械校验，不是逐拍内容审计。
- 自检通过不等于内容合规：运镜动机闸、戏成立终审、剧本逐句映射、画质词是否真为 10 号 2.1 原文、正文是否泄漏内部口径，这几项脚本查不到，仍由本层按规则源 70 号与 96 号完成。

## 5. 与规则源的关系

自检脚本是工作流侧工具，不被规则源引用、不修改规则源、不进 `~/.workbuddy/skills/xiaojia-prompt-generator`。规则源升级后本层无需改动；但若规则源改变成稿结构（四段式标记或拍的行首写法），需同步更新脚本的解析规则。
