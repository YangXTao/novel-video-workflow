## 0. 双模式与总流程

先判定模式：用户要求生成、续写、改镜、扩写、压缩、重构或批量分镜时进入生成模式；用户要求诊断、对比、维护或修改 skill 时进入维护模式，只处理 skill，不生成分镜。两种要求同时出现时先完成维护，再按最新参数生成。

生成模式固定经过：

```text
M0接收输入
→ M1建立事实账本与缺口账本
→ M2识别输入形态/任务模式/内容类型/题材/风格/模型/项目参数/触发事实
→ M3锁定项目契约并读取96号执行契约
→ M4生成当前任务文件+子节依赖清单，逐项读取，建立规则卡/资产卡/状态卡
→ M5按规则卡组装自然句，逐拍/逐镜/逐场回执，连续性与状态回写，合规复验，质检和最终收口
→ 输出
```

### 0.1 运行启动闸

每次任务必须内部完成以下八步，任何一步没有结果都不得直接输出最终分镜：

1. 建立原始输入包：原文、参考图、已有镜头、用户明确要求和上一镜交接状态全部保留。
2. 建立事实账本：场次、时间、地点、人物、台词原句、动作、物件、因果和结果逐项登记；完整剧本逐项登记。
3. 锁定项目契约：项目级秒数、局部时长覆盖、画幅、目标模型、语言、画质轨、色板、参考图、内容类型和喜剧模态。
4. 判定触发事实：技能、法术、法阵、领域、巨型实体、地点变化、闪回、声音、台词、场景地标和用户限制分别标记。
5. 先读 `references/96-规则执行契约与证据回执.md`，生成当前任务的文件+子节依赖清单；只读文件名、标题或范围不算读取完成。
6. 逐项读取依赖并建立规则卡：每条启用规则必须有触发事实、输出位置、冲突优先级和验收证据。
7. 逐拍生成并回写：规则只进入适用的画面句、声音句或状态包；不适用规则标明原因，不制造剧情。
8. 依次完成合规复验、连续性、证据回执、成像盲测和最终收口；有未读取依赖、无证据硬规则、事实漏项、时长冲突或状态冲突就返工或请求用户决策。

内部状态严格区分：`已读取 → 已启用 → 已落字 → 已验收`。只有“已验收”可以放行；`不适用`必须有未命中触发条件，不能用来遮盖漏读。

## 1. 输入形态与任务模式

输入形态四选一：零散想法、小说章节、完整剧本、分镜草稿。小说章节先完成场景切分、人物识别、事件链、对白归属和叙述/心理可视化；完整剧本执行“保留·补全·纠错”，启用铁律48，禁止删除台词、动作、物件或情节节点；分镜草稿只改用户指定范围并保留镜头意图。

任务模式可一主一副：生成、扩写、压缩、重构、校验、续写、改镜、多镜批量。校验模式只输出问题清单；其他模式按用户要求输出最终正文。改镜模式除指定镜头外保持其余内容不变，修改后只重验受影响链路。

## 2. 内容类型分流

| 内容类型 | 主依赖 | 强规则边界 |
|---|---|---|
| 打戏/动作交锋 | 00、13、10、11、12、41；有武器加02/90，有三层材质加93，特效动态加94，体修加92 | 当拍攻击因果、目标部位、物理反馈和动作运镜生效；普通交锋开局即战；不把文戏和法术大场面规则全量套入 |
| 文戏/日常/情感 | 00、20、40、50；喜剧/萌系按触发事实加61 | 外显表演、空间、台词、声音和情绪画质生效；不触发每击必爆、战斗十二闸、能量核爆和强制EWS |
| 追逐/高速运动 | 00、12中位移相关子节、35、37、40、41、50、60 | 位移、动线、惯性、前景掠过和空间连续生效；只有确有攻击或碰撞时才追加攻击反馈 |
| 法术/大场面 | 00、30、41；法阵加91，技能状态加95，大型法术形态加97，动态加94，材质加93 | 先判小法术、范围法术、法阵、巨型实体、法相或领域，再只启用对应规则；EWS、比例尺、声音五层和冲击反馈均条件化 |
| 混合叙事/打中谈 | 按时间轴分段读取动作、文戏、法术依赖 | 同一拍动作因果优先，台词声色和微表演叠加；互斥画质和强规则不得同时硬套 |
| 写实/纪录片/2D/定格 | 61、60及当前内容类型依赖 | 由风格轨道整体替换冲突的UE5默认、三层能量、玄幻核爆和强动态模糊，不并列堆叠矛盾词 |

M2先定内容类型，M3才允许调素材。题材只能补制作表达，不能覆盖剧本事实、用户指定、项目契约和已确认状态。

## 3. 项目契约与冲突优先级
字数范围说明：成稿字数上限仅针对每个S镜头的四段式完整正文：每个S镜头≤5000字。全章总稿字数不限。分段配额按单镜计算，静态画质项全集在每镜各声明一次，各镜仍须自包含。超限沿用铁律54原有压缩或请求拆镜规则，秒数规则不变。

项目契约至少包含：项目标识、输入形态、任务模式、项目级镜头秒数、局部时长覆盖、画幅、目标模型、语言、画质轨道、色板、参考图绑定、内容类型、喜剧模态、剧本事实、用户覆盖项、未决冲突，以及v12.9新增的 total_word_budget（每个S镜头≤5000字，分段配额①≤250/②≤400/每拍打戏220-280文戏180-240/④≤300，超限压缩或请求拆镜）。

冲突顺序固定为：系统/安全/版权合规 ＞ 用户明确要求和原始剧本事实 ＞ 项目契约与已确认连续性状态 ＞ 当前内容类型硬规则 ＞ 专门模块细则 ＞ 题材默认 ＞ 素材库默认 ＞ 模型适配和审美优化。用户明确说“只要、不要添加、保持单一”时，自动补全让位；用户明确点名秒数时，项目级和局部范围按原话锁定。

项目秒数是项目级规格：开局点名一次后全项目沿用；明确说“当前镜头/当前段落”才形成局部覆盖；未指定时仅在首次建立本项目契约时使用10秒作为可覆盖默认值，不跨项目继承。旧模板中的“每镜10秒”“30秒时间轴”“8—12镜”等不覆盖当前契约。节拍时间总和必须等于当前镜头总时长，1.5—2.0秒只是动作镜头常规建议，不是所有类型的固定值。承接拍若由37号锁定为1秒，只占该拍的局部时长，剩余时间重新分配。

## 4. 依赖读取与规则卡

所有生成任务先读96号。96号把路由组展开为“文件+子节+触发目的”；已声明依赖必须读取完整适用子节，不能只看摘要。每条启用规则建立规则卡：规则ID、触发事实、当前要求、输出位置、依赖文件/子节、冲突优先级、正文或状态证据、状态。输出位置必须具体到画质段、角色场景段、某一拍时间轴、声音句、负面段或状态包。

生成顺序固定：先锁场景五层、固定地标、角色和道具状态；再做全局节奏和动线；技能/法术出现时先读95建立技能锁定和语义卡，命中大型法术条件才读97并按30选择对应类别；随后按当前镜头任务组装自然句。每个镜头结束后回写角色、道具、场景、光源、技能、特效残留、声音尾部、镜头末态和下一镜必须承接的事实。

完整剧本启用铁律48：台词、动作、物件和情节节点逐项映射到镜号和时间段。容量不足时不得删句，必须保留全部原文并请求用户决定加镜、加长或拆分。

## 5. 输出协议

最终只输出用户要求的分镜正文；规则卡、依赖清单、状态表、证据回执、导演模拟报告和返工记录默认内部静默。字段只用于内部组装，最终落稿按当前内容类型使用自然画面语言；校验模式或用户明确要求展示过程时才输出结构化信息。

每镜必须按项目契约自包含，不能写“同上”“同前”“画质同前”。当前轨道画质基准、场景状态、角色当前状态、空间关系、声音和负面约束按适用规则落字。参考图只压缩外观复读，不压缩动作、表情、战损、站位、道具和空间关系。

`Time Ramp`仅在当前画质基准或用户明确要求的视觉技术参数中保留；不得在时间轴中作为内部标签单独出现。内部编号、分支名、S-Packet、语义卡、三混合、尺度换算和ACT/FPV/POV等必须转译为可拍画面语言。

## 6. 三层验收

P0逐拍检查当前片段已启用的逐拍硬规则和正文证据；P1逐镜全量检查承接、时长、拍段求和、状态、运镜、人数、声色、参考图、剧本映射和规则卡证据；P2逐场全量检查场景、地标、体力/环境损耗、技能残留、节奏、爆发/余波、声音、喜剧模态和跨镜交接。只有次要审美修饰可以抽检，硬规则和完整剧本内容不得抽检。

合规替换、压缩、模型适配、格式整理或导演Agent修正后，必须重验受影响规则。最终依赖读取顺序为：当前依赖子节 → 70质检 → 99最终执行指令 → `100-现行口径总覆盖.md`。100号必须最后读取并刷新规则卡。
