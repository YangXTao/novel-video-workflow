## 96-规则执行契约与证据回执

============================================================

# 模块十九·规则执行契约与证据回执（v12.9现行）

> 定位：本模块是主控与各 reference 之间的唯一执行接口。它不新增一套画面风格，也不替代 00、10、20、30、37、40、50、61、70、95 等内容模块；它负责把“本次输入有什么事实、哪些规则被触发、必须读哪些子节、正文应出现什么证据、镜头结束后要回写什么状态”串成一条可追踪链。
>
> 核心原则：**读到标题不等于读到规则，读到规则不等于规则生效，规则生效不等于正文已执行，正文出现也不等于状态已回写。** 四个状态必须分开判断：`已读取 → 已启用 → 已落字 → 已验收`。
>
> 输出边界：本模块的依赖清单、规则卡、证据回执、状态包、返工原因和内部标签均为内部状态，最终分镜不得出现模块编号、规则编号、依赖表、证据表或“已通过”等元话语。

## 19.1 唯一执行链

任何生成、续写、改镜、扩写、重构、多镜批量任务都必须按以下顺序执行；不得跳过中间状态直接从输入跳到正文：

```text
原始输入包
→ 事实账本与缺口账本
→ 项目契约锁定
→ 场景/段落内容类型路由
→ 当前任务依赖清单
→ 逐依赖读取指定文件与子节
→ 全局规则卡、场景卡、角色卡、技能卡、声音卡、空间卡
→ 镜头草稿
→ 规则证据回执
→ 状态账本与下一镜交接包
→ 合规替换后再验收
→ 成像盲测与最终收口
→ 输出
```

任何一步未完成，后续状态不得标记为完成。尤其禁止以下替代：

- 读到 reference 文件名，不能代替读取该文件的适用子节。
- 读到“铁律0–51”，不能代替判断当前镜头实际触发了哪些铁律。
- 写了“空间锚定”“技能连续”“特效完整”等概括词，不能代替把对应细节写进画面句。
- 做了抽检，不能代替对剧本内容、用户明确要求、项目时长和当前触发的硬规则逐项核对。
- 合规替换、长度压缩、模型适配或格式整理之后，必须重新验收被影响的规则，不得沿用替换前的通过状态。

## 19.2 项目契约：生成前先锁定

每个项目或独立连续片段首次运行时，内部建立唯一项目契约；后续镜头读取并继承，不在每镜重新猜测：

```text
PROJECT_CONTRACT {
  project_id: 项目/剧集/片段内部标识
  input_form: 零散想法 / 小说章节 / 完整剧本 / 分镜草稿
  task_mode: 生成 / 扩写 / 压缩 / 重构 / 校验 / 续写 / 改镜 / 多镜批量
  shot_duration: 用户指定的项目级秒数；未指定时首次建立本项目契约使用10秒可覆盖默认值，不跨项目继承
  shot_duration_scope: 项目级 / 当前段落覆盖 / 当前单镜覆盖
  total_word_budget: 字数范围说明：成稿字数上限仅针对每个S镜头的四段式完整正文：每个S镜头≤5000字。全章总稿字数不限。分段配额按单镜计算，静态画质项全集在每镜各声明一次，各镜仍须自包含。超限沿用铁律54原有压缩或请求拆镜规则，秒数规则不变。
  aspect_ratio: 横屏/竖屏/用户指定比例
  target_model: 目标模型及语言、负面词能力
  visual_contract: 画质基准、色板、渲染轨、参考图绑定
  content_types: 全片或各段落内容类型
  comedy_mode: 无 / A小框 / B实体化 / C混合；喜剧项目首次锁定后沿用
  narrative_facts: 剧本事实、台词、动作、物件、人物关系
  user_overrides: 用户明确指定的颜色、数量、运镜、时长、风格、模型、参考图
  open_conflicts: 尚未解决的事实冲突或容量冲突
}
```

锁定规则：

1. 用户明确指定的项目秒数优先于默认秒数，并通过铁律51锁到本项目；“当前镜头XX秒”只在用户明确限定局部时形成局部覆盖，不能偷偷改成全项目规格。
2. 参考图绑定只解决外观复读，不删除当前状态、动作、战损、表情、位置和空间关系。
3. 内容类型允许按段落或时间轴切换；混合叙事不是把打戏、文戏、法术所有规则同时打开。
4. 题材默认只能补制作表达，不能覆盖剧本事实、用户指定或已经锁定的状态。
5. 未知制作参数可以用最小必要默认补足，并标记为内部默认；未知剧情事实、角色关系、关键技能结果不能伪装成已知事实。

## 19.3 事实账本：先拆事实，再拆镜头

输入解析后建立四张账本；完整剧本必须逐场建立，小说章节必须先转成事实账本再分镜：

### A. 剧情事实账本

记录场次、时间、物理地点、人物、台词原句、动作、物件、事件因果、情绪外显线索和场景结果。完整剧本形态启用铁律48：台词、动作、物件逐项编号，之后每一项都必须映射到镜号和时间段；没有映射证据就不能放行。

### B. 资产与空间账本

记录角色外观/战损/姿势/朝向/位置/武器，道具位置与状态，场景五层、固定地标、光源、天气、地面材质、已消耗地标、破坏累积、180°轴线和三层纵深。读取 `40` 与 `35`，跨镜读取 `37`。

### C. 技能与特效账本

只有出现技能、法术、法阵、能量、召唤、领域或用户明确要求技能连续性时启用。读取 `95` 建立技能锁定表和技能语义卡；大型法术另外按 `30` 的触发条件调用大型法术形态与比例尺规则。每个技能必须至少能回答：谁释放、依托什么、长什么样、从哪里到哪里、作用谁/什么、结果是什么、留下什么、下一镜保留什么。

### D. 声音与输出账本

记录角色音色、台词归属、口型、气口、环境音、动作音、静默点、BGM条件、模型是否支持原生声音、负面词能力和输出语言。读取 `50` 与 `60`。模型适配不能删除剧情台词，只能在能力不足时改变呈现方式并保留原句。

## 19.6 规则卡：把抽象规则变成输出任务

每条已启用规则在内部形成一张最小规则卡，不需要展示思考过程：

```text
RULE_CARD {
  rule_id: 规则编号或子节
  trigger: 当前输入中的触发事实
  requirement: 本次必须完成的一句话要求
  output_slot: 画质段 / 角色场景段 / 某拍时间轴 / 声音句 / 负面段 / 状态账本
  dependency: 必须读取的文件与子节
  evidence: 最终正文或状态包中的可定位事实
  conflict: 与哪些规则可能冲突
  precedence: 冲突时服从哪一层
  state: 已读取 / 已启用 / 已落字 / 已验收 / 不适用 / 返工
}
```

`output_slot`是防止规则空置的关键：没有明确落点的规则只能作为背景知识，不能标记为已执行；如果一条规则要求“每拍都写”，验收时必须逐拍查，不得改成每场概括。

## 19.7 生成与回执：逐拍、逐镜、逐场三层都必须有证据

### 逐拍

每拍先读取上一拍落点和当前场景卡，再只执行当前片段有效规则。动作片段至少落实：镜头位置/目标/终点、人物发力或动作因果、空间锚定、目标与结果、环境或物件响应；法术片段追加技能生命周期中本拍发生的阶段；文戏片段落实空间距离、身体外显、物件/参照物和台词/声音中的适用项。没有发生的阶段标记为不适用，不制造剧情。

### 逐镜

每镜验收：项目时长与拍段求和、首拍承接、角色和道具状态、镜头内人数、运镜去重、声色、参考图精简边界、负面词/正向约束、当前镜头触发规则证据。合规替换、模型适配或压缩后重新验收受影响项目。

### 逐场

每场验收：场景五层与地标生命周期、角色体力和环境损耗双曲线、技能/特效残留、空间轴线、节奏曲线、爆发点与余波、声音层次、喜剧模态统一、剧本事实映射。完整剧本的内容映射是全量验收，不是抽检。

## 19.8 证据回执的最小格式

内部只保留结论，不展示隐藏推理；每条适用硬规则都要有如下回执：

```text
[EVIDENCE]
rule=铁律/子节
object=场次/镜号/拍段/台词或技能
required=本次要求
location=正文或状态包中的可定位位置
status=PASS / NA / REWORK / USER_DECISION
reason=缺项、冲突、容量不足或用户覆盖原因
```

`PASS`只允许在正文已经出现具体证据且没有被后处理删除时使用。`NA`必须有明确触发条件未命中的原因；不能因为忘记读取而写NA。`REWORK`必须回到生成阶段修改；`USER_DECISION`只用于时长、镜头数、剧情事实等无法静默裁决的冲突。

## 19.9 返工顺序与冲突仲裁

发现缺项或矛盾时按以下顺序处理：

1. 系统/安全/版权合规。
2. 用户明确要求与原始剧本事实。
3. 项目契约与已经确认的连续性状态。
4. 当前内容类型的硬规则。
5. 技能/场景/声音/运镜等专门模块。
6. 题材默认与素材库默认。
7. 模型适配和审美优化。

返工只修改受影响的最小范围，但凡修改了时长、台词、动作因果、技能状态、空间、场景破坏、转场、声音或颜色，必须重跑对应的跨镜状态和证据回执。不能用新增特效掩盖事实冲突。

## 19.10 最终放行闸

最终输出前必须同时满足：

- 当前任务的依赖清单全部完成，必读子节没有只读摘要的情况。
- 所有适用规则卡均为`已验收`或有明确`不适用`证据；不存在只“已读取”未落字的硬规则。
- 完整剧本的台词、动作、物件逐项有映射；容量冲突已让用户决策。
- 每镜时长、每拍求和、项目锁定秒数和跨镜承接一致。
- 技能、场景、角色、道具、环境、声音状态已回写下一镜交接包。
- 合规替换、模型适配、压缩和格式整理之后，受影响规则已重新验收。
- 模块70的成像盲测六问全部能用当前正文回答；不能回答就返工。
- 最终正文不出现内部编号、依赖、规则卡、证据回执、分支判断和未经允许的工程参数。
- 【v12.9新增硬指标】每个S镜头≤5000字；打戏复合运镜去重种数＞拍数（10s≥7/30s≥15、三维≥10）、文戏10s≥4；打戏已过第0叙事闸且势曲线/逆转/胜负闭环齐；成稿工程参数零泄漏（画幅占比%与②段三混合配比%除外）；场景未指定时已默认临海草坡鲜亮场景而非灰蒙蒙。任一不满足→REWORK，不得放行。
