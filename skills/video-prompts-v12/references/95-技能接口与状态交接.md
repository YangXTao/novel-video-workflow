## 95-技能接口与状态交接

============================================================

# 模块十八·技能接口与状态交接（v12.9现行接口）

> 定位：本模块是技能生命周期、角色/空间连续性与质检之间的**共享接口层**。它只定义数据契约、读写时机和异常处理，不另立一套角色、空间或特效状态来源。角色、道具、空间、环境和特效的事实账本仍由 `40` 号模块维护；本模块规定技能状态如何接入、交接和验收。每次启用前先由 `96` 号执行契约生成依赖清单，本模块不得自行扩展触发范围。
> 生效范围：仅当本场存在法术、技能、法阵、能量特效、召唤物或用户明确要求技能连续性时启用。纯文戏、日常和无技能场景不因本模块强制增加技能字段。
> 输出边界：以下字段、接口名、状态包和校验过程只在内部使用，最终分镜正文不得出现本模块编号、字段名或内部标签。

## 95.1 唯一接口原则

1. **单一事实来源**：
   - 角色身份、服装、战损、身体状态、站位和动线，读取并回写 `40-角色资产与连续性.md`。
   - 场景地标、光源、道具位置、环境破坏和空间拓扑，读取并回写 `40` 与 `35-场景环境锚定.md`。
   - 技能的形态、阶段、轨迹、命中结果、环境改写和余波，通过本模块的技能接口接入上述账本。
   - `30-法术大场面.md` 负责法术视觉编排与条件化表现，不得另建一张互相独立的跨镜状态表。
2. **主控仲裁**：由 `SKILL.md` 根据输入形态、任务模式、内容类型、题材和用户显式要求生成本场有效规则集合；本模块只处理已经被主控启用的技能字段。
3. **最小必要记录**：没有发生变化的字段沿用上一状态，不在正文机械复读；需要输出的内容必须能从状态账本追溯到剧本事实或用户指定。
4. **禁止隐式升级**：资料中的示例数值、模型专属参数、固定时长、固定米数、频率、透明度和冷却值，除非来自用户或剧本，不得通过本接口升级为全局硬规则。

## 95.2 技能锁定表

项目或段落首次出现技能时，内部建立一条技能锁定记录：

| 字段 | 必填条件 | 记录内容 |
|---|---|---|
| 技能标识 | 必填 | 用户/剧本名称；未命名时生成内部稳定标识，不把内部名写入正文 |
| 释放者 | 必填 | 角色、群体、环境或外部装置；写清控制关系 |
| 属性与视觉主色 | 有属性/视觉要求时 | 属性来源、主色、对撞色和与其他特效的可辨差异 |
| 媒介 | 技能依托媒介时 | 掌心、兵器、符纸、法阵、地面、天空、道具等 |
| 形态 | 必填 | 可拍的轮廓、材质和空间层级；单体不得只用“光团/能量”交差 |
| 轨迹 | 会移动或扩散时 | 起点、方向、路径、速度感、转向条件和目标位置 |
| 目标 | 有攻击/作用对象时 | 角色、部位、道具、场景锚点、区域或必经落点 |
| 命中/作用反馈 | 有接触或效果时 | 目标形变或改变、镜头反应、声音和可见结果 |
| 环境改写 | 影响场景时 | 地面、建筑、天气、光源、空间拓扑的变化及持久性 |
| 余波与消散 | 技能结束或转场时 | 残留特效、残留声音、回流/衰减/崩解/遮罩及下一状态 |
| 限制 | 剧本/用户明确或因果需要时 | 施法窗口、受力、资源、冷却、失控或破绽；未知时不擅自编造数值 |
| 当前阶段 | 必填 | 未显现、聚合、附着、脱体、飞行、接触、持续、衰减、消散、被打断或失败 |

### 95.2.1 形态与关系拆分

同一关键词不能自动套用同一视觉规则。生成前先区分：

- **角色自身巨化/实体法身**：形态继承角色的服装、面部锚点、武器和控制关系；有实体核心，环境负责比例尺。
- **能量拟形**：由能量形成的动物、兵器或手掌；不自动继承角色的实体生理结构，需写能量轮廓、材质、控制链和消散方式。
- **独立召唤物/巨兽实体**：是独立单位，记录实体材质、重量、呼吸/运动惯性、与释放者的距离和控制关系。
- **领域异象/环境改写**：不是角色或独立生物，记录作用边界、空间规则、受影响对象、退出/破域条件和恢复方式。

“法相”“金身”“化身”等模糊词必须依据剧本、角色动作和控制关系归入上述类别；无法判定时选择不改变既有事实的最小解释，并在内部标记待确认，不同时套用互斥材质规则。

## 95.3 技能语义卡

技能锁定完成后，为当前技能建立可读语义卡。语义卡是生成和质检的中间契约，不是最终输出字段：

```text
【技能语义卡】
技能标识：
释放者与控制关系：
属性/主色/对撞色：
媒介与发源点：
主体轮廓与材质：
空间层级与参照物：
轨迹（起点→方向→路径→目标）：
作用结果（命中/被挡/击空/持续/偏转/失败）：
目标反馈与镜头反馈：
环境改写与持久痕迹：
余波、消散与声音尾部：
限制/触发条件：
当前阶段：
证据来源：剧本原文 / 用户指定 / 题材默认 / 素材卡
```

语义卡的每一项必须标记证据来源。题材默认只能补足制作表达，不能覆盖剧本事实或用户指定；没有证据的工程数值不填入全局契约。

## 95.4 生命周期

技能按事件而不是固定秒数推进。可用阶段为：

`未显现 → 聚合/结形 → 附着或脱体 → 轨迹运动 → 接触/作用 → 结果扩散 → 余波残留 → 衰减/回收/消散`

🔴v12.9起承爆残成稿动词模板（把内部状态机翻译成画面动词，落稿强制用这套动词而不是状态名）：
- 起（无→聚）："从[身体/武器/地面]一点亮起/一缕起"——写清发源点，禁一拍蹦出完整特效。
- 承（生长/拉长，从小到大）："沿径向逐节点点亮/向上堆叠/向外铺开/层层展开"——跨1-2拍长成，给尺度阶梯，禁瞬现贴图。
- 爆（命中）："白热芯爆亮→主色中层雾化→对比色边缘炸开→物理碎片飞溅"——分层炸开+对撞点白热+作用到镜头与环境。
- 残（消散）："按惯性衰减/属性烙痕/余能沉降/粒子重力沉降/场景不复原"——写清怎么散，禁止凭空消失。
四段缺一即REWORK（铁律53）。法阵另按铁律31/53立体生长（半透明矮圆柱能量体、向外铺开或向上堆叠）。

- 小法术、局部特写或压缩镜头可以合并阶段，但不得制造与剧本相反的因果顺序。
- 大型法术、法阵、领域和用户要求的完整演示，至少显式表现“释放源定位 → 结构建立 → 释放/运动 → 接触或空间改写 → 结果 → 余波/消散”中的必要阶段；是否展开完整层级由主控有效规则集合决定。
- 技能被打断、偏转、被挡或击空时，当前阶段必须更新为对应结果，并把未完成的能量、声音、光照和环境影响交给下一镜。
- 同一技能跨镜继续时，下一镜只继承仍存在的状态；已经消散的部分不得凭空复活。

## 95.5 与 `40` 状态账本的交接包

每次镜头结束时，内部生成一份最小 S-Packet，写入 `40` 的共享账本：

```text
S-Packet {
  scene_id: 场景标识,
  shot_id: 镜号,
  time_anchor: 尾帧时间与机位,
  actors: 角色位置/朝向/动作势能/身体状态/服装战损,
  skills: 技能标识/释放者/当前阶段/形态/轨迹落点/能量状态,
  props: 武器与关键道具位置及状态,
  environment: 地标/光源/空间拓扑/破坏与改写状态,
  residuals: 特效残留/声音尾部/尘雾/光照影响,
  next_hook: 下一镜必须承接的事实,
  evidence: 本包各项对应的剧本或用户依据
}
```

交接规则：

1. **创建**：技能首次出现，先建立锁定表和语义卡，再写首镜；没有释放者、媒介或目标的事实时，只补可见最小信息。
2. **读取**：每镜生成前读取上一镜 S-Packet；跨场景时同时读取场景资产卡，避免技能状态覆盖角色/空间事实。
3. **更新**：每次释放、转态、命中、被挡、击空、偏转、持续、消散或环境改变后更新对应字段；未变化字段继承，不重复另起来源。
4. **交接**：镜尾把“下一镜必须承接的事实”写入内部包。若下一镜是时间跳跃、闪回、梦境或平行时空，先建立新的时间/空间上下文，再决定哪些字段可继承。
5. **异常返工**：发现状态冲突时，按“剧本事实 → 用户指定 → 已确认账本 → 内容类型规则 → 题材默认”顺序回溯；不能用新特效掩盖冲突。修复后重写受影响镜头并重新交接。
6. **关闭**：技能明确消散、被替代、离开当前场景或项目段落结束时关闭当前记录；余波仍存在则保留只读残留，直到消散或被新事实覆盖。

## 95.6 条件化触发矩阵

| 情况 | 至少读取/更新 | 可省略 |
|---|---|---|
| 无技能的文戏/日常 | `40` 的角色、空间和道具状态 | 技能锁定表、生命周期、EWS、攻击反馈 |
| 单个小法术/局部特效 | 技能语义卡的释放者、形态、轨迹/作用、结果、残留 | 完整八层大法术链、EWS；除非用户指定 |
| 大型法术/法阵/领域 | 完整语义卡、生命周期、环境改写、余波、比例尺与声音接口 | 与本镜无关的攻击型“每击”规则 |
| 法术对撞/护盾受力 | 双方技能卡、接触点、消长、偏转/穿透结果、环境和镜头反馈 | 不发生的阶段或未经要求的固定数值 |
| 法相/能量拟形/独立召唤物 | 类型判定、控制关系、实体性/材质、空间层级、比例尺、消散 | 互斥类别的规则 |
| 写实/纪录片/定格风格 | 生命周期与物理结果按风格替换 | 玄幻能量核爆、默认三层强效、无依据参数 |

## 95.7 接口验收

放行前静默检查：

- 技能是否有明确释放者、形态、媒介或合理的环境来源；
- 移动技能是否写明起点、方向、目标和结果；
- 法术是否按当前阶段连续，未把聚合、接触、消散顺序打乱；
- 技能造成的角色、道具、光源、地标和环境变化是否已回写 `40`；
- 跨镜是否只继承仍存在的状态，未复原残留或凭空改变颜色、形态、位置；
- 法相、能量拟形、独立召唤物和领域异象是否只命中一套类别规则；
- 任何工程数值是否有用户/剧本证据，未被误写成全局硬规则；
- 正文是否把内部接口名、S-Packet、语义卡、阶段标签或证据来源转译成自然画面语言。

接口失败时状态为“返工”，不得直接进入最终输出。
