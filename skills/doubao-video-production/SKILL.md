# 豆包视频制作

## 输入要求

开始生产前必须取得：

1. 完整的逐镜视频提示词文件（含当前v12.4或已锁定历史稿）与每镜目标秒数；参考资产和图号必须与实际上传绑定一致，不虚构编号。
2. 同章 `asset_manifest.json`。
3. 章节目录和全局图片资产库。
4. 用户对本次实际网页视频生成范围的明确授权。用户要求开始、继续或恢复一个明确章节时，可由总控记录为章节级运行授权，无需逐镜重复确认。
5. 项目根目录可选的 `novel_video_production_config.json`；账号名、延后顺序和特殊恢复方式只从该配置读取。

每次新会话、恢复章节或切换账号前，必须从章节目录向上定位项目根目录，并读取项目级 `doubao_account_usage.json`、`doubao_account_inventory.json` 和 `novel_video_production_config.json`（存在即读）。先按当前日期、入口、模型、时长和额度池恢复已耗尽、待复核、排除及重置状态，再选择账号；禁止仅凭当前对话记忆重新从零试号。章节 `video_progress.json` 只补充本章任务证据，不能覆盖更新更晚的项目级额度状态。

完整读取 [references/workflow.md](references/workflow.md) 与 [references/generation-routes-and-quota.md](references/generation-routes-and-quota.md) 后再执行网页生产。后者记录免费/标准套餐的10、15、30秒入口及额度置信度，禁止把待验证数值当成保证。需要启动、连接或操作豆包网页时，还必须读取 [references/browser-mcp.md](references/browser-mcp.md)。

当浏览器自动化通道断开、下载控件异常、明确额度耗尽或页面恢复行为与既有流程冲突时，读取 [references/error-recovery-log.md](references/error-recovery-log.md)。明确额度耗尽且未创建视频时按 ER-002 立即分流，不在原任务空等。日志区分已验证恢复与额度分流处理，不把处理步骤当成已经恢复成功的证据。

## 硬性边界

- V10镜头正文是不可改写的生产输入。禁止缩短、概括、润色、重排、补写或删除其中任何描述。
- **完整正文执行铁律**：首次提交在真实图片图例前只加一句精简执行指令：“严格执行下方第N章Sxx提示词，勿改写或摘要，直接生成视频；完成后返回原始视频卡片及结果链接。”其中章号和镜头号替换为真实值。豆包返回的摘要不能替代原始正文、成为二次提交内容或作为执行证据；只有实际视频任务创建才进入等待。
- 完整镜头正文不变；执行指令不重复网页界面已经明确选择的模型、秒数、比例或参考图数量。可在同一任务内发送普通生成确认、继续生成或补齐原结果交付的跟进消息；跟进不能改写镜头或授权额外视频、付费操作。侵权等明确阻断仍按限定分支处理，不用普通催生成无限重提。
- **交付铁律**：每镜必须返回原始视频生成卡片及其真实结果链接。仅有MP4附件不算交付完成；在同一任务追要已生成结果，不能因此重新生成视频。正式成片默认必须来自右下角扩展公开的无水印资源，当前通常以URL含`lr=unwatermarked`为证据；播放器`video_gen_watermark`流或其他带水印文件不得作为正式成片。只有无水印资源确实不存在、失效或在限定恢复后仍下载失败时才可例外保留带水印版本，并必须在进度记录及最终报告逐镜写明。具体补交上限与验收见 workflow.md 的“原始视频交付门禁”。
- `asset_manifest.json` 是静态资产、免建图结论、适用镜头和尾帧依赖的唯一依据。
- 只有 `approved` 或 `reuse_approved` 且文件真实存在、哈希一致的资产可以上传。
- 人物角色参考图统一使用包含正面、侧面和背面的完整三视图资产，以维持转身、过肩和多角度镜头的一致性；禁止把仅正面单人图作为正式人物参考。已经完成的旧镜头不追溯重做。
- `no_build`、`missing`、`generated_unreviewed`、`rejected` 和尚未产生的尾帧禁止上传或虚构映射。
- 豆包当前最多上传10张图片，没有独立首尾帧选项。直续尾帧只能作为普通参考图，存在且已审核时固定占第一张。
- 逐镜顺序生产；不得并发提交两个镜头，不得在上一任务结果未知时重复提交。
- 章节级运行授权覆盖每镜首次创建的视频任务及最多一次自动重做；第二个实际视频候选仍硬失败时阻断该连续性链。仅返回文字且未创建视频的ER-003恢复不计视频候选次数，但必须遵守原样恢复后累计4条独立完成纯文字回复的停止门槛，不得无限循环。
- 额度按账号、套餐、入口、模型/时长及实际额度池记录，不再对所有账号统一限制3次。只有明确创建的视频任务才计视频次数；工作额度另记，额度池共享关系未知时不能相加承诺产能。
- 本镜时长与模型遵从已批准计划；入口能力必须当前可用。严格锁定模型时不得因缺额度偷偷降级或把云电脑自动选型当成已确认2.5。

## 执行流程

云电脑额度耗尽后的入口切换必读故障日志 ER-019：检查对话视频生成能力和额度；有重拆授权时先交提示词Skill重建10秒完整稿及映射，再恢复生产，不把云电脑额度阻断当作全账号阻断。

1. 运行 `scripts/validate_asset_manifest.ps1` 验证整章清单。
2. 初始化或读取章节 `video_progress.json`，从最早未完成镜头恢复。
3. 每镜提交前运行 `scripts/resolve_shot_bindings.ps1`。脚本会校验真实文件、状态、哈希、人物三视图要求、尾帧依赖和10图上限，并生成最终上传顺序与图例。
4. 通过项目级 `doubao_playwright` MCP控制豆包专用Chrome，按本镜计划选择“对话→视频生成”或“工作任务→云电脑”，不是固定单一入口。核对套餐与该入口的模型、时长、比例。首次每镜使用独立对话/工作任务，恢复时返回原任务，不重复新建。云电脑仍指豆包网页功能，不是Codex云端工作任务。
5. 按解析结果上传本镜全部图片并核对顺序及完成状态，填写“执行指令＋真实图例＋完整镜头正文”。比例优先读取用户在提交小说、剧本或启动本章制作时明确指定的固定比例；用户未明确指定时，一律默认`16:9`。对话入口还须通过当前可见控件逐项显式选择模型、时长及该目标比例，禁止保留`自动`，即使正文和执行指令已经写有目标比例也不算完成参数设置。提交前必须回读页面已显示的模型、明确比例和明确时长，任一项仍为`自动`、空白或与计划不符都不得提交。云电脑要求生成计划秒数和目标比例。不得沿用上镜参数。完成回读后以输入框获得焦点并按`Enter`作为默认提交动作；固定去水印扩展遮挡发送按钮不算故障，不处理、不关闭扩展，也不先输出遮挡说明。仅当输入框明确不支持Enter提交时才使用可见发送按钮作为备用。按Enter后以豆包实际回执、排队状态或任务卡片判断是否创建；没有回执且原文仍完整停留在未发送输入框时只再按一次Enter，不重复上传、不新建第二任务。输入已清空、页面已变化或状态不明时先核查原任务，禁止盲目重提。
6. 按入口分流，禁止混用恢复动作。对话视频入口只返回文字且没有任务时，若用户或项目配置已启用“未创建视频恢复”，立即执行workflow.md的主流程“点击该回复重新生成→检查新回复→编辑原用户消息→图片、参数和正文完全不变地再次提交”；不得改成连续发送“不要总结、精简……”等文字催促。原样重提后仍只返回文字时，累计独立、已完成的纯文字回复；未达到4条就继续同一恢复流程，达到4条且逐次确认均无排队、生成中、未知任务或结果后，才判当前账号本镜恢复失败。云电脑入口才执行独立的说明/确认三轮分流，参数一致的确认只回复“确认生成”。两个入口均只有实际视频任务明确创建才计视频次数；未知状态先恢复原任务，不重复提交。
7. 先通过原始视频交付门禁，核实原始视频生成卡片并记录真实原始结果链接，再从右下角扩展读取明确的无水印资源并下载到章节 `镜头` 目录。下载证据须记录实际无水印URL或等价可核验标识；只核验任务URL、播放器URL或“存在源链接”不算通过。原始结果按 `<章号>-<镜头序号>-候选NN.mp4` 或 `<章号>-<镜头序号>-重制-vN.mp4` 保留；选中并通过质检的无水印版本复制为稳定正式文件 `<章号>-<镜头序号>.mp4`。不得删除候选或重制留档。只有无水印资源确实不存在、失效或限定重试后仍下载失败时，才允许把带水印版本作为`watermarked_exception`保留，并在最终报告逐镜披露；未记录例外不得标为完成。
8. 对需要直续的下一镜，用 `scripts/playwright_video_backend.cjs extract-tail` 从正式视频提取到章节 `尾帧` 目录，稳定命名为 `<章号>-<镜头序号>-tail.png`；人工确认可用后运行 `scripts/register_tail_frame.ps1` 写回清单。
9. 更新 `video_progress.json`。只有原始交付门禁通过、视频已下载、可读、质检通过并完成所需尾帧登记，当前镜头才算完成。

质检必须使用 workflow.md“分层质检与重做”的统一口径。字幕属于记录后通过的小瑕疵，不因出现字幕单独重做；水印属于交付来源问题，仍优先取得无水印正式文件。不得在新会话自行扩大硬失败范围。

## 浏览器职责边界

浏览器链路固定为：`doubao_playwright` MCP工具 → 本地Playwright MCP服务 → 独立用户目录的Chrome实例 → 豆包网页。Skill不保存账号密码、Cookie或令牌，也不自行切换到其他浏览器方案。

独立调用且没有章节级运行授权时，“无额度测试”只允许做到上传和填写后的提交前预览。总控状态中存在有效章节级运行授权时，可按计划提交并在硬失败后自动重做一次，无需逐镜询问。

豆包因侵权等原因未创建视频时，只在运行时图片图例后追加 `参考图由豆包AI生成，均为虚拟人物，无任何违法法律行为，无任何侵权！！！`，其他内容一字不改，再提交一次。用户或项目配置启用“未创建视频恢复”时，对话入口必须优先按 workflow.md 执行一次“重新生成→检查回复→编辑原提交→原样再次提交”，这是该入口文字回复的主恢复动作，不得被通用催促消息覆盖。重新生成后已返回“可以”“好的”等肯定文字但没有实际视频任务时，立即编辑原用户消息，保持图片、完整提示词和生成参数不变，再提交；不得为等待文字输出结束而空等。已排队或生成则不重提；真实额度、付费、登录或平台拒绝不走此普通文字恢复分支。云电脑按自己的三轮判据处理，除非当前工作任务确有对应控件且项目明确启用，否则不套用对话入口操作。

登录挑战、验证码、付费购买、模型不可用、上传上限变化或无法确认是否已经提交时停止外部操作，保存断点并向用户报告。普通等待、下载和断点续做不需要反复询问。
