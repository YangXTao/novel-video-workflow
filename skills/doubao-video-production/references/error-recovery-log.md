# 故障恢复记录与历史问题索引

## ER-019｜云电脑额度耗尽却未检查对话视频入口

**状态/来源：** 用户明确要求的故障分流，2026-09-07补录；不是对话入口当前余额充足的证明。

1. 云电脑已明确额度耗尽且没有活动/未知视频任务时，保存原任务和额度证据，随即检查同一已授权账号“对话→视频生成”的真实模型、时长、比例及额度。云电脑办公额度耗尽不自动等于对话视频额度耗尽；若页面确认共享限制，则尊重该限制。
2. 对话入口支持原镜参数且有额度时，使用真实参考图和完整原稿提交。只回文字且没有任务时，沿用ER-003及项目启用的“重新生成→编辑原用户消息→原样重提”规则。
3. 对话入口仅可生成10秒而原镜是15秒时，读取用户/项目已有的重新拆分授权；有授权则交视频提示词Skill将尚未生成的内容重建为完整10秒镜头，保留全部剧情、对白、逐句声线情绪、动作因果及跨镜状态。先保存原稿、父子镜头映射、新时间轴和资产绑定，验证后以批准模型及16:9提交。不得只将原15秒稿的执行指令改为10秒或压缩删词。
4. 若未授权变更时长，则尝试其他获准账号的原参数路线或同章已批准的10秒镜头。账号顺序、标准套餐预留、原有章节顺序及次数限制仍按项目执行；通用Skill不硬编码账号名。
5. 只有已授权的对话、云电脑候选均不可用，且没有可执行的同章工作时才等待。按入口分别记录检查结果，不能仅凭云电脑回复把整个账号或整章判为额度耗尽。

**恢复成功证据：** 实际创建视频任务后才记submitted/generating并计视频次数；仅切到对话入口或看到可选控件不算生成成功。


## 记录状态与复发检查

本文件集中索引本工作流遇到的问题；跨图片、提示词、浏览器的问题指向所属 Skill 的现有处理规则，不赋予视频 Skill 改写正文或操作其他浏览器的权限。
- **已验证案例**：有原任务/文件状态证明某一次处理成功，不保证下次必然成功。
- **既有规则/用户经验**：已有处理步骤，但本次整理未重新实际运行。
- **未解决/原因待核实**：保留症状与限制，不把推测或“重新登录后可用”写成旧登录已恢复。

每次实际故障，在章节事件记录中保存：发生时间、章节/镜头或资产、账号与入口、原任务URL、原始错误摘要、是否已创建任务、采用的ER编号、已执行步骤、结果证据和下一步。无任务时不填假任务ID，未查明原因写unknown。重启、切会话不清零已执行的重提/补交次数。

## ER-003｜对话只回文字，“可以生成”后没有视频

**状态/来源：** 已验证案例：本项目第43章 S01 的 video_progress.json 记录原文编辑重提后于2026-09-06 23:09出现视频生成已提交；这不证明后来该账号的登录恢复成功。
**处理：** 核实无活动或未知视频结果，按项目已启用的恢复循环执行“重新生成→检查返回→编辑原用户消息→图片、参数、正文不变再次提交”。返回肯定文字但无视频任务即可进入编辑重提，不把文字流式输出当成视频进度。每镜一次循环，结果持久化。
**退出：** 有真实任务即等待；明确额度耗尽走ER-002，登录或平台拒绝不使用此循环。
**完整规则：** [workflow.md](workflow.md)“对话入口：保留重新生成与原文重提”。

## ER-004｜云电脑问确认、只给方案，三轮仍未启动

**状态/来源：** 既有规则；来自用户反复报告的云电脑未创建问题。
**处理：** 仅确认原图片、正文和参数时回复“确认生成”；只有方案且核实无任务时跟进生成。首次完成回复加最多两次跟进，三条完成回复均无实际视频启动则记本轮路线不可用；三次轮询同一条回复不算三轮。任务执行中或结果未知先恢复原任务。
**退出：** 额度耗尽直接ER-002；10秒对话候选只用于已有授权的10秒稿，不将15秒原稿原地改短。
**完整规则：** [generation-routes-and-quota.md](generation-routes-and-quota.md)“云电脑连续三轮未启动视频生成”。

## ER-005｜生成已完成但下载窗口/扩展面板没显示

**状态/来源：** 用户经验：“如果视频下载窗口没有显示，可以试着刷新一下界面”。
**处理：** 先保存原任务URL并核查生成卡片。确认无未保存编辑内容后，仅刷新同一结果页一次，等结果及扩展加载，再检查下载入口；不新建生成任务。
**退出：** 控件仍缺失时记录交付/下载问题，按ER-006/007检查，不循环刷新或重复生成。

## ER-006｜扩展下载导致等待下载事件超时

**状态/来源：** 既有已记录兼容路径，见workflow的“去水印扩展的下载兼容”。
**处理：** 扩展可能通过Chrome扩展接口下载，不触发普通Playwright下载事件。先检查实际新文件，再核对扩展面板识别出的当前结果及公开资源地址；按原候选顺序下载并验证时长、可读性、哈希。正式成片必须优先且默认使用扩展公开的无水印资源，当前通常以`lr=unwatermarked`为证据；播放器`video_gen_watermark`地址不得作为正式来源。
**退出：** 扩展未识别或地址未显示时，不臆造无水印地址；依次刷新原任务、重开原始卡片、复查扩展并限定重试无水印URL。仍失败时才可记录`watermarked_exception`，并在进度记录和最终报告逐镜披露镜号、失败证据、恢复动作及实际文件；未记录例外不得以播放器带水印源冒充无水印原片。
**完整规则：** [workflow.md](workflow.md)“等待与下载”。

## ER-007｜只交付MP4附件，扩展识别不到原始视频

**状态/来源：** 用户第42章交付反馈；根因不能仅凭附件形式推定为所有案例相同。
**处理：** 首次提交带原始卡片交付铁律。视频已生成但缺原始卡片/链接时，在同一任务补交一次，明确“不要重新生成视频”。原任务URL、重传附件URL不冒充原始结果链接。
**退出：** 仍不能补交则保存已有结果和original_delivery_missing；不为交付格式重做视频。能下载不等于已无水印。
**完整规则：** [workflow.md](workflow.md)“原始视频交付门禁”。

## ER-008｜专用Chrome不可见、后台有视频声音

**状态/来源：** 本会话用户反馈；已有浏览器运行约束，不认定某个启动机制已被证明是唯一根因。
**处理：** 核对既有Chrome进程、所属桌面会话、配置目录和可见窗口；使用原MCP恢复已有窗口。仅必要QA时播放，检查后暂停。保持当前任务和登录目录。
**退出：** 禁止因界面不可见擅自换worker、Windows用户、CDP控制器或无头浏览器；不强杀所有Chrome。
**完整规则：** [browser-mcp.md](browser-mcp.md)“可见窗口与可恢复连接”。

## ER-009｜Chrome右侧/底部灰边，页面显示不全

**状态/来源：** 本会话截图与浏览器配置规则；窗口调整后仍需现场复核。
**处理：** 已有窗口先恢复normal再最大化；检查实际窗口和网页视口。既定有界面配置为headless=false、viewport=null，配置变更只影响后续启动；不为灰边重启仍在生成的浏览器。
**完整规则：** [browser-mcp.md](browser-mcp.md)。

## ER-010｜登录丢失、切换旧账号提示“参数错误”

**状态/来源：** 未解决的历史账号恢复问题。部分账号重新登录后可用，不代表原账号会话已找回；持久化目录存在不证明登录令牌仍有效。
**处理：** 保存错误与受影响账号，核对原目录、原桌面用户和启动链路。涉及目录或启动配置的更改前，按用户要求备份并验证；不清空、替换或迁移配置目录，不读取敏感浏览器存储。
**退出：** 未验证的账号保持login_required/unknown。不能把重新登录包装成历史登录恢复；不能反复切换失效账号并声称已修复。根因、可恢复性必须用实际证据说明。
**完整规则：** [browser-mcp.md](browser-mcp.md)；ChatGPT同类问题参见[图片浏览器说明](../../chatgpt-image-production/references/browser-mcp.md)。

## ER-011｜不断开标签页、未提交，临时对话地址丢失

**状态/来源：** 图片生产既有排错规则及用户“也不发送”反馈。
**处理：** 从图片账本和已打开页面恢复原任务；临时c/WEB地址不能作为持久恢复地址，等正式UUID。DOM加载完成后仍需等侧栏/消息异步出现。不得反复打开首页覆盖已有结果。
**退出：** 按实际上传、填写、提交、生成状态推进；只有填写不算生成。查无原任务时记录未知，不盲重提。
**所属流程：** [ChatGPT图片排错](../../chatgpt-image-production/references/troubleshooting.md)“临时对话地址”。

## ER-014｜参考图无中生有、no_build被算成缺图、尾帧尚未产生

**状态/来源：** 第44章资产交接曾把免建图动态特效计为缺图，随后重算静态缺图；静态图齐不代表视频提交就绪。
**处理：** 仅approved/reuse_approved真实文件可映射；no_build仅作文字约束。按实际镜头依赖单独检查尾帧，缺尾帧不能编造图号；人物三视图按一张图计数，总数遵守项目上限。
**退出：** 校验、绑定脚本通过后才上传；仍有真实依赖则保存阻断，不把所有镜头一律设ready。
**完整规则：** [workflow.md](workflow.md)“运行时参考图解析”。

## ER-016｜提示词格式变化、时间轴缩水、对白缺声线情绪

**状态/来源：** 本会话多次用户反馈；已在提示词执行合同记录，新增文字规则不等于全部历史产物自动合格。
**处理：** 回到当前活动母版和锁定正文，读取适用完整规则组；逐句核对声线、情绪、嘴部状态及时间轴动作因果。长文本交付文件，生产阶段按完整正文回读/哈希确认，不自行概括。

## ER-017｜Bad Request、工具参数错误与平台拒绝混为一谈

**状态/来源：** 用户曾报告Bad Request及图片平台内容拒绝；原始请求详情不足，根因待核实。另有browser_click工具缺少target的实际参数校验错误，不能等同网站失败。
**处理：** 保存报错发生层次（本地工具校验/MCP传输/HTTP响应/网页生成拒绝）、参数结构和是否已提交；不记录凭证。缺工具字段按当前工具定义修正；结果未知先查原任务。
**退出：** 不宣称Bad Request一定由敏感词、网络或账号导致；明确平台拒绝按既有边界处理，不能用普通文字恢复无限重投。

## ER-018｜提前进入下一章、定时任务把目标缩成只等一个镜头

**状态/来源：** 第43/44章先后顺序纠正及本会话额度自动化记录。
**处理：** 先读取用户最新章节顺序与真实完成状态；上一章完成门槛未满足不能推进下一章。调度保留整章目标、实际断点、可执行的同章任务及解除阻断后的后续步骤，不能把当前等待点误写成最终目标。
**退出：** 无实际页面检查只报告基于旧记录的等待；用户已暂停自动化则保持暂停。规则更新不自动重启视频生产或改写已有镜头。


## ER-002｜已确认额度耗尽后仍空等原任务

**识别：** 原任务明确返回额度耗尽或恢复时间，且确认没有实际视频任务、排队进度或待核验结果。此时没有视频可等待；不能记为 generating，也不执行普通文字回复的重新生成循环。

**处理：**

1. 保存账号、入口、目标秒数、原任务链接、原始额度回复和观察时间；恢复时间只记录页面明确值，未知留空。未创建视频则视频计数不增加。
2. 立即按ER-019检查对话视频入口，再按项目已授权账号选择可用路线；需调整时长时执行已有重拆授权和完整重建流程。已耗尽的额度池在出现恢复证据前不反复提交。普通确认、仅返回文字的原文重提规则继续保留，但不用于明确额度阻断。
3. 同参数候选全部不可用时，将受影响镜头记为 blocked、reason=quota_exhausted，列出已检查候选及排除理由。检查同章已授权的独立镜头和准备工作；仅在项目允许且没有前镜尾帧/语义依赖时推进独立镜头，遵守单任务提交和章节顺序。
4. 只有确实没有可推进工作时才进入调度等待。自动化必须保留完整章节目标和恢复后的后续镜头流程，不能缩成永久只检查当前镜头。用户已暂停的自动化不得自行重启。
5. 每次检查区分“实际读取当前页面”和“根据已记录恢复时间尚未到期跳过”；没有访问页面不能声称已核验额度仍未恢复。新额度证据出现后重新选择路线，不因旧日期持续挂起。

**边界：** 不改镜头秒数或正文、不启用被排除账号、不购买或消费重置机会来解决额度不足。此记录仅固化分流方法，不承诺任何账号已恢复或已完成视频。


## ER-001｜视频已生成后，点击下载控件导致 Playwright MCP 传输关闭

**适用证据：** 页面已显示原始视频生成卡片或 `<video>`，并明确出现“视频生成好了/已完成”；触发下载或去水印扩展控件后，MCP 返回 `Transport closed`、连接超时或无法继续读取同一页面。

**处理：**

1. 先持久化已有原始卡片证据、任务会话 URL、可见视频源链接、镜头编号和“已创建任务”状态；不得将传输断开误写成视频失败。
2. 不点击重新生成、不编辑原提交、不切换账号，也不把该任务计为未知后重提。
3. 仅恢复本地 `doubao_playwright` MCP 服务，并重新连接同一专用 Chrome 配置目录；恢复后先回到原任务确认卡片与视频仍在，再继续扩展无水印资源读取、下载、命名和质检。
4. 若当前 Codex 会话的 MCP 连接无法重新挂接，保留断点并通过同一会话的后续恢复或已建立的任务监控再次尝试；不得为绕过连接故障启动新的豆包任务。
5. 只有页面明确失去原任务且无法核验已生成结果时，才标为 `unknown` 并报告；此前的卡片/视频证据优先。

**不适用：** 登录、验证码、付费、侵权拒绝、明确额度耗尽、模型不可用或视频任务从未创建。这些按对应的既有停止或恢复分支处理。
